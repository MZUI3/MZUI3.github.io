# 문체 교정 기준 (2026-11-09)

목표: 모든 글을 **해라체 평서문(~한다/~이다)** 의 학술적 문체로 바꾸고, AI가 쓴 티가 나는 표현을 줄인다. **정보·주장·수치·예시·순서·소제목 구성은 그대로 둔다.**

## 1. 종결어미 변환 (필수, 남김없이)

본문 문장, 목록 항목, 표 셀, 인용 블록(`>`), 그림 캡션(`_Figure ..._`), front matter의 `description` 모두 바꾼다.

| 원문 | 수정 |
|---|---|
| 사용합니다 / 학습합니다 (동사) | 사용한다 / 학습한다 |
| 중요합니다 / 필요합니다 / 가능합니다 / 비슷합니다 / 충분합니다 (형용사) | 중요하다 / 필요하다 / 가능하다 / 비슷하다 / 충분하다 |
| 입니다 / 아닙니다 | 이다 / 아니다 |
| 있습니다 / 없습니다 | 있다 / 없다 |
| 했습니다 / 됐습니다 / 였습니다 | 했다 / 됐다 / 였다 |
| 됩니다 / 봅니다 / 줍니다 / 집니다 / 납니다 / 씁니다(쓰다) / 갑니다 | 된다 / 본다 / 준다 / 진다 / 난다 / 쓴다 / 간다 |
| 큽니다 / 작습니다 / 빠릅니다 / 다릅니다 / 높습니다 / 깁니다(길다) | 크다 / 작다 / 빠르다 / 다르다 / 높다 / 길다 |
| 늘어납니다 / 줄어듭니다 / 바뀝니다 / 떨어집니다 | 늘어난다 / 줄어든다 / 바뀐다 / 떨어진다 |
| 셈입니다 / 것입니다 / 때문입니다 | 셈이다 / 것이다 / 때문이다 |
| 정리합니다 / 다룹니다 / 살펴봅니다 / 살펴보겠습니다 | 정리한다 / 다룬다 / 살펴본다 / 살펴본다 |
| ~할 수 있습니다 / ~해야 합니다 | ~할 수 있다 / ~해야 한다 |
| ~일까요? / ~할까요? | ~일까? / ~할까? (가능하면 평서문으로: "~인지 따져 본다") |
| ~하세요 / ~해 보세요 | ~해야 한다 / ~하면 된다 / ~하는 것이 좋다 |
| ~해 봅시다 / ~생각해 봅시다 | ~를 생각해 보자 / ~를 가정한다 |
| ~했죠 / ~거든요 / ~네요 | ~했다 / ~이기 때문이다 / ~이다 |

명사 뒤 서술격 조사는 받침 유무와 관계없이 **`~이다`로 통일**한다("조건부이다", "범위이다", "하나이다"). 단, "~것이다", "~셈이다", "~때문이다"는 원래대로.

함정: "뒤집니다"는 대부분 *뒤지다(뒤처지다)* 의 활용이므로 "뒤진다"로 바꾼다("뒤집는다"·"앞선다" 아님). "깁니다"는 *길다* → "길다", "답니다/랍니다" 같은 인용형은 "~다고 한다".
동사를 동의어로 바꾸지 않는다(어색할 때만 최소한으로). 시제는 원문을 따르되, 앞뒤 절과 시제가 어긋나 비문이 되는 경우만 맞춘다.

동사와 형용사를 구분해야 한다. "-하다" 형용사(중요·필요·가능·유사·비슷·충분·동일·간단·명확·유리·불리·적합·안정적…)는 `~하다`, 동작 동사는 `~한다`.
"~ㄴ다" 뒤에 연결되는 인용(`~라고 합니다` → `~라고 한다`)도 같이 바꾼다.

## 2. AI 티 나는 표현 줄이기 (판단해서, 내용은 보존)

1. **강조용 굵은 글씨 남발.** 본문 문단 안에서 평범한 구절이나 절 전체를 `**`로 감싼 것은 풀어 준다. 남기는 것: 처음 정의되는 핵심 용어·방법 이름, 목록/인용 블록의 라벨(`**논문**:`, `**1. ~.**` 같은 항목 머리), 표 안의 라벨. 문단 하나에 굵은 글씨가 2개를 넘지 않게 하는 정도가 기준이다. 핵심 결과 수치나 글 전체의 요약 문장에 붙은 굵은 글씨는 하나 정도 남겨도 된다. 굵은 글씨를 풀 때 `**`만 지우고 글자는 그대로 둔다.
2. **상투 구문.** "흥미롭게도", "놀랍게도", "주목할 점은", "한 문장으로 요약하면", "~이 핵심입니다", "~라는 점이 핵심이다", "~것이 전부입니다", "바로 ~입니다", "결국", "즉," 를 문장마다 반복하면 빼거나 담백하게 바꾼다. 의미가 있는 곳(요약 문장 자체, 논리적 귀결)은 둔다.
3. **"A가 아니라 B" 대비 공식의 반복.** 한 문단에 여러 번 나오면 하나만 남기고 나머지는 평서문으로 푼다. 원래 주장이 대비인 경우(논문이 실제로 대비함)는 둔다.
4. **수사적 질문으로 문단 열기.** "왜 그럴까요?", "그렇다면 ~할까요?" 같은 질문은 평서문으로 바꾸거나 해라체 질문(`~할까?`)으로 짧게 둔다.
5. **독자에게 말 거는 투.** "~해 보세요", "기억해 두세요", "여기서 잠깐" 같은 구어는 학술적 서술로 바꾼다.
6. **과한 비유·감탄.** 내용과 관련된 비유는 두되 "마법처럼", "놀라운" 같은 수식은 뺀다.
7. **번역투**(~에 대해, ~을 통해, ~되어지다, ~에 있어서)는 자연스럽게 고친다.

## 3. 건드리지 말 것

- 코드 블록(```), `text` 출력 블록, 인라인 코드, 수식(`$$...$$`), 링크 주소, Liquid(`{% %}`), HTML 태그, 이미지 경로
- front matter의 `description` 이외 필드(title, date, categories, tags, math 등). title은 바꾸지 않는다.
- 숫자, 단위, 고유명사, 영어 기술 용어, 인용한 논문 제목, 참고문헌 목록 항목
- 소제목(`#`)의 문구는 종결어미가 합쇼체일 때만 바꾼다.
- 문단 나누기, 목록 순서, 표 구조

## 4. 작업 방식

- 파일 하나씩 전체를 읽고, 위 규칙을 적용한 전문을 파일에 다시 쓴다. 줄바꿈은 CRLF를 유지한다(편집 후 스크립트로 확인).
- 다 쓴 뒤 `python -X utf8 docs/style-review-2026-11-09/check_style.py <파일들>` 을 돌려 `BAD`가 없게 한다. 남은 합쇼체(`~니다`, `~요.`)가 있으면 고친다.
- 마크다운 렌더링 문제(캡션 줄 바로 다음 줄에 빈 줄 없이 본문이 붙는 등)를 발견하면 고치지 말고 보고서에 적는다.
- 내용이 틀렸거나 이상해 보이면 고치지 말고 보고서의 "내용 확인 필요"에 적는다.
