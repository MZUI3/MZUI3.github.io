> [VLA 총정리 글]({% post_url 2026-10-19-vision-language-action-models %})의 일곱 번째 모델입니다. **GR00T N1**(*An Open Foundation Model for Generalist Humanoid Robots*, NVIDIA, 2025)의 핵심은 모델보다 **데이터를 쌓는 방식**에 있습니다. 사람이 원격조작한 실제 로봇 데이터는 비싸고 적으니, 시뮬레이션과 비디오 생성 모델로 데이터를 불리고, 행동 라벨이 없는 사람 영상까지 학습에 씁니다. 모델 가중치와 데이터, 시뮬레이션 벤치마크를 모두 공개했습니다. 논문이 없는 후속작 N1.5는 6장에서 함께 다룹니다.

## 1. 문제: 로봇 데이터는 "섬"이다

언어 모델은 인터넷 텍스트라는 하나의 거대한 데이터로 학습합니다. 로봇 데이터는 그렇지 않습니다. 로봇마다 몸의 구조, 센서, 자유도, 제어 방식이 달라서 데이터가 서로 섞이지 않는 **섬(data island)**처럼 흩어져 있습니다. 특히 휴머노이드는 두 팔과 손가락을 한꺼번에 원격조작해야 해서 데이터를 모으기가 더 비쌉니다.

GR00T N1의 답은 두 가지입니다.

1. 몸이 달라도 하나의 모델로 학습하는 구조(몸별 encoder/decoder)
2. 실제 로봇 데이터 밖의 데이터까지 쓰는 **데이터 피라미드**

## 2. 구조: System 2 + System 1

| 구성 | 내용 |
|---|---|
| System 2 (VLM) | **Eagle-2**(SmolLM2 LLM + SigLIP-2 이미지 인코더), 이미지 224×224 → pixel shuffle → 프레임당 64개 토큰. L40에서 10Hz |
| System 1 (행동) | flow matching으로 학습한 **DiT**(Diffusion Transformer), 16 step chunk를 4번의 노이즈 제거로 생성. 120Hz로 행동 출력 |
| 몸별 모듈 | 상태 encoder, 행동 encoder, 행동 decoder를 몸(embodiment)마다 따로 둔 MLP |
| 크기 | 전체 2.2B (VLM 1.34B), 16 step chunk 생성에 L40 bf16으로 63.9ms |

### VLM은 중간 층만 쓴다

이미지와 지시문을 VLM에 넣은 뒤, LLM의 **마지막 층이 아니라 12번째(중간) 층**의 특징을 가져옵니다. 이쪽이 추론도 빠르고 정책 성공률도 높았다고 합니다. 사전학습과 후학습 모두에서 VLM의 언어 부분은 얼려 둡니다.

### DiT: self-attention과 cross-attention을 번갈아

DiT는 노이즈 제거 단계 $$\tau$$를 adaptive layer norm으로 넣는 Transformer입니다. GR00T의 DiT는 두 종류의 층을 번갈아 쌓습니다.

- **self-attention**: 로봇 상태 토큰과 노이즈가 섞인 행동 토큰끼리
- **cross-attention**: VLM이 낸 이미지·언어 토큰을 key·value로

[π0]({% post_url 2026-10-21-pi0 %})는 VLM과 action expert가 같은 self-attention 안에서 섞이는 mixture-of-experts 구조였습니다. GR00T는 cross-attention으로만 잇기 때문에, VLM과 행동 모델을 각각 다른 구조로 바꿔 끼우기 쉽습니다. 논문도 이 유연성을 장점으로 듭니다.

### 몸마다 다른 입출력

로봇마다 상태와 행동의 차원이 다르므로, **몸마다 따로 둔 MLP**가 상태와 (노이즈 단계와 함께) 행동을 공유 임베딩 공간으로 옮기고, 마지막에 다시 몸별 decoder가 행동 차원으로 되돌립니다. 가운데 DiT는 모든 몸이 공유합니다. 아래는 이 구조를 작게 줄인 예입니다. flow matching 표기는 π0 글과 같습니다.

```python
import torch
import torch.nn as nn

torch.manual_seed(0)
D, H, K = 256, 16, 4                                   # 공유 임베딩 크기(예제용), action chunk 길이, 노이즈 제거 step 수
dims = {"humanoid": 44, "single_arm": 7, "latent_action": 32}   # 몸마다 다른 행동 차원(예시)

class EmbodimentAwareDiT(nn.Module):
    def __init__(self):
        super().__init__()
        self.enc = nn.ModuleDict({k: nn.Linear(d + 1, D) for k, d in dims.items()})   # 몸별 encoder: 행동 + 시간 τ
        self.dec = nn.ModuleDict({k: nn.Linear(D, d) for k, d in dims.items()})       # 몸별 decoder
        self.self_attn = nn.MultiheadAttention(D, 4, batch_first=True)                 # 행동 토큰끼리 (공유)
        self.cross_attn = nn.MultiheadAttention(D, 4, batch_first=True)                # VLM 토큰을 봄 (공유)

    def forward(self, body, noisy_actions, tau, vl_tokens):
        x = self.enc[body](torch.cat([noisy_actions, tau.expand(*noisy_actions.shape[:2], 1)], dim=-1))
        x = x + self.self_attn(x, x, x)[0]
        x = x + self.cross_attn(x, vl_tokens, vl_tokens)[0]
        return self.dec[body](x)                                                       # 속도(velocity) 예측

model = EmbodimentAwareDiT()
vl_tokens = torch.randn(1, 64 + 20, D)                 # VLM 중간 층 특징: 이미지 64 토큰 + 지시 20 토큰
with torch.no_grad():
    for body, d in dims.items():
        a = torch.randn(1, H, d)                        # τ = 1(노이즈)에서 시작
        for k in range(K):
            tau = torch.full((1, 1, 1), 1 - k / K)
            a = a - (1 / K) * model(body, a, tau, vl_tokens)
        print(f"{body:13s} → action chunk {tuple(a.shape)}")
per_body = {b: sum(p.numel() for p in [*model.enc[b].parameters(), *model.dec[b].parameters()]) for b in dims}
shared = sum(p.numel() for n, p in model.named_parameters() if "attn" in n)
print("몸별 encoder·decoder 파라미터:", per_body, f"| 공유하는 attention 파라미터: {shared:,}")
```

```text
humanoid      → action chunk (1, 16, 44)
single_arm    → action chunk (1, 16, 7)
latent_action → action chunk (1, 16, 32)
몸별 encoder·decoder 파라미터: {'humanoid': 23084, 'single_arm': 4103, 'latent_action': 16928} | 공유하는 attention 파라미터: 526,336
```

새 로봇을 붙일 때 늘어나는 것은 작은 encoder와 decoder뿐이고, 행동을 만드는 핵심 부분은 모든 로봇의 데이터로 함께 학습됩니다. 세 번째 "몸"인 `latent_action`은 실제 로봇이 아닙니다. 아래에서 설명할, 영상에서 뽑은 가상의 행동입니다.

## 3. 데이터 피라미드

| 층 | 데이터 | 양 | 행동 라벨 |
|---|---|---|---|
| 꼭대기 | 실제 로봇: GR-1 휴머노이드 원격조작, Open X-Embodiment 일부, AgiBot-Alpha(로봇 100대의 14만 궤적) | 적음 | 실제 행동 |
| 중간 | 합성: 시뮬레이션 궤적, 비디오 생성 모델로 만든 영상(neural trajectory) | 중간 | 자동 생성 |
| 바닥 | 사람 1인칭 영상(Ego4D, EPIC-KITCHENS 등 7종), VLM의 웹 데이터 | 많음 | 없음 |

아래층은 넓은 시각·행동 사전 지식을, 위층은 실제 몸에서의 정확한 실행을 줍니다.

### 꼭대기: 실제 로봇

Fourier GR-1 휴머노이드를 사람이 원격조작해 모았습니다. VIVE 트래커로 손목 위치를, Xsens 장갑으로 손가락을 추적해 역기구학으로 로봇 동작에 옮기고, 20Hz로 기록합니다. 잡기·옮기기 같은 세부 동작과 이를 묶은 상위 작업을 두 단계로 주석했습니다.

### 중간: 시뮬레이션과 생성 영상

- **시뮬레이션**: DexMimicGen은 사람 시연 몇십 개를 물체 중심의 조각으로 나눈 뒤, 새 물체 위치에 맞게 변환해 이어 붙이고, 시뮬레이터에서 성공한 것만 남깁니다. "A를 B에서 C로 옮기기" 형태의 54가지 조합마다 1만 개씩, 사전학습용으로 54만 개를 만들었습니다. 후학습용까지 합치면 **78만 궤적, 사람으로 치면 6,500시간(9개월)** 분량을 **11시간** 만에 생성했습니다.
- **생성 영상**: 이미지에서 영상을 만드는 비디오 생성 모델을 88시간의 원격조작 데이터로 fine-tuning한 뒤, 같은 첫 프레임에서 새로운 지시("왼손으로 오이를 바구니에")로 영상을 생성했습니다. 멀티모달 LLM이 장면의 물체를 보고 물리적으로 가능한 지시만 만들고, 생성된 영상이 지시를 제대로 따르는지 다시 LLM이 걸렀습니다. 그렇게 **88시간을 827시간 분량으로 약 10배** 불렸습니다. L40 GPU 3,600장으로 1.5일(약 10만 5천 GPU-시간)이 걸렸습니다.

### 바닥: 행동 없는 영상에서 행동 뽑기

사람 영상과 생성 영상에는 로봇 행동이 없습니다. 두 가지로 라벨을 만듭니다.

- **Latent action**: VQ-VAE의 encoder가 현재 프레임과 조금 뒤 프레임을 보고 그 사이의 변화를 작은 벡터로 압축하고, decoder는 그 벡터와 현재 프레임으로 뒤 프레임을 복원하도록 학습합니다. 학습이 끝나면 encoder가 "이 두 장면 사이에 무슨 행동이 있었나"를 알려 주는 역동역학 모델 역할을 합니다. 이 벡터를 하나의 가상 몸("LAPA")의 행동으로 보고 같은 flow matching loss로 학습합니다. 흥미롭게도 같은 latent action이 로봇에서도 사람에서도 "오른팔을 왼쪽으로" 같은 비슷한 움직임에 대응했습니다.
- **IDM 라벨**: 실제 로봇 데이터로 학습한 역동역학 모델(IDM)이 생성 영상의 행동을 추정합니다.

실제 로봇 데이터에는 실제 행동과 latent action을 함께 학습 목표로 씁니다. 사전학습에는 H100 약 5만 GPU-시간이 들었고, 최대 1,024장을 썼습니다.

## 4. 실험

### 사전학습 모델 바로 쓰기

GR-1에서 두 작업을 시켰습니다. 왼손 쪽에 둔 물건을 선반에 올리려면 왼손으로 집어 오른손에 건네야 하는 작업에서 **76.6%**, 처음 보는 물체를 처음 보는 용기에 넣는 작업에서 **73.3%**였습니다.

### 시뮬레이션 벤치마크 (작업당 시연 100개로 후학습)

| 벤치마크 | BC-Transformer | Diffusion Policy | GR00T-N1-2B |
|---|---|---|---|
| RoboCasa (24개 작업, 단팔) | 26.3 | 25.6 | **32.1** |
| DexMG (9개 작업, 양팔·손) | 53.9 | 56.1 | **66.5** |
| GR-1 (24개 작업, 휴머노이드) | 16.1 | 32.7 | **50.0** |
| 평균 | 26.4 | 33.4 | **45.0** |

시연 30개와 300개에서도 GR00T N1이 항상 앞섰습니다. 수도꼭지 돌리기 작업에서는 Diffusion Policy가 11.8%, GR00T N1이 42.2%였는데, Diffusion Policy는 작업이 무엇인지부터 헷갈리는 경우가 많았습니다.

### 실제 GR-1 휴머노이드

| 작업 종류 | DP (데이터 10%) | DP (전체) | GR00T N1 (10%) | GR00T N1 (전체) |
|---|---|---|---|---|
| 물건 담기 | 3.0 | 36.0 | 35.0 | **82.0** |
| 서랍·캐비닛(넣고 닫기) | 14.3 | 38.6 | 62.0 | **70.9** |
| 산업용(부품 담기, 붓기, 건네기) | 6.7 | 61.0 | 31.0 | **70.0** |
| 두 로봇 협업 | 27.5 | 62.5 | 50.0 | **82.5** |
| 평균 | 10.2 | 46.4 | 42.6 | **76.8** |

데이터를 10%만 쓴 GR00T N1(42.6%)이 전체 데이터를 쓴 Diffusion Policy(46.4%)와 거의 같았습니다. 동작도 더 부드럽고 잡기도 정확했습니다.

### 생성 영상을 후학습에 섞으면

후학습 때 생성 영상을 실제 데이터와 1:1로 섞자 RoboCasa에서 평균 4.2~8.8%p, 실제 GR-1에서 5.8%p가 올랐습니다. 라벨 방식은 데이터가 아주 적을 때(작업당 30개)는 latent action이 조금 낫고, 데이터가 늘수록 IDM이 더 나았습니다. IDM은 데이터가 많을수록 실제 행동에 가까운 라벨을 만들기 때문입니다.

### 후학습이 잊게 만든 것

사전학습 모델은 왼쪽에 놓인 사과를 왼손으로 집어 오른손에 건넨 뒤 바구니에 넣었습니다. 그런데 오른손만 쓰는 데이터로 후학습한 모델은 이 건네기를 하지 못했습니다. 후학습 데이터에 없던 능력은 후학습 과정에서 사라질 수 있다는 관찰입니다.

### 논문이 밝힌 한계

짧은 탁상 작업 위주이고, 이동하면서 하는 긴 작업은 앞으로의 과제입니다. 더 강한 VLM이 공간 추론과 언어 이해를 높일 것으로 보고, 합성 데이터가 물리 법칙을 지키면서 다양해지기 어렵다는 점도 한계로 꼽습니다. 적은 자원으로는 A6000 한 장에서 DiT와 몸별 모듈만 fine-tuning할 수 있습니다(배치 최대 200).

## 5. 이후: GR00T N1.5 (2025.05)

NVIDIA는 Computex 2025에서 N1.5를 발표하고 6월에 연구 페이지를 공개했습니다. 논문은 없으므로 아래 수치는 NVIDIA 연구 페이지의 자체 평가입니다.

**바뀐 점**

- **VLM 완전 고정**: 사전학습과 fine-tuning 모두에서 VLM을 얼립니다. VLM은 grounding(지시한 물체 찾기)을 강화하도록 fine-tuning한 Eagle 2.5로 바꿨습니다(GR-1 장면 grounding IoU 40.4, Qwen2.5-VL-3B는 35.5).
- **Adapter 단순화**: VLM 안에서 비전 인코더와 LLM을 잇는 MLP를 단순화하고, LLM에 들어가는 이미지·텍스트 토큰 임베딩에 LayerNorm을 더했습니다. NVIDIA는 이 변경이 지시 따르기와 일반화를 크게 높였다고 설명합니다.
- **FLARE**(Future LAtent Representation Alignment): 미래 프레임을 생성하는 대신 모델이 **미래 장면의 임베딩**에 맞춰지도록 하는 목표를 flow matching loss에 더했습니다(가중치 0.2). 행동 라벨이 없는 사람 1인칭 영상에서도 배울 수 있습니다.
- **DreamGen(GR00T-Dreams)**: 월드 모델로 새 작업을 하는 로봇 영상을 생성해 학습 데이터로 씁니다. NVIDIA는 사람이 모으면 3개월 가까이 걸릴 데이터를 36시간 만에 만들었다고 발표했습니다.
- 학습: H100 1천 장으로 25만 step, 배치 16,384

**결과(N1 → N1.5)**

| 평가 | N1 | N1.5 |
|---|---|---|
| 실제 GR-1 지시 따르기 비율 | 46.6% | **93.3%** |
| 실제 GR-1 전체 성공률 | 43.3% | **83.0%** |
| RoboCasa, 작업당 시연 30개 | 17.4 | **47.5** |
| DreamGen으로만 배운 12개 새 동작 | 13.1% | **38.3%** |
| Unitree G1, 과일 담기 | 44.0% | **98.8%** |

처음 보는 물체는 0%에서 15%가 됐고, 그 물체가 나오는 사람 영상으로 FLARE 후학습을 하면 55%까지 올랐습니다.

## 6. 해석

**1. 데이터 피라미드는 "무엇을 어디서 배우나"의 분업이다.** 넓은 바닥(사람 영상, 웹)은 물체와 동작의 일반 지식을, 중간(시뮬레이션, 생성 영상)은 로봇 몸으로 바꾼 다양한 상황을, 꼭대기(실제 원격조작)는 실제 몸의 정확한 행동을 맡습니다. 실제 데이터 88시간이 생성 영상 827시간, 시뮬레이션 6,500시간 분량으로 불어난 숫자가 이 전략의 핵심입니다. [RT-1]({% post_url 2026-10-20-rt-1 %})이 17개월 동안 로봇 13대로 모은 데이터와 비교하면 데이터를 "모으는" 시대에서 "만드는" 시대로 넘어가는 신호입니다.

**2. Latent action은 영상을 로봇 데이터로 바꾸는 번역기다.** 행동 라벨 없는 영상을 쓰려면 행동을 지어내야 합니다. latent action은 그 영상 자체를 "하나의 몸"으로 취급해, 모델 구조를 바꾸지 않고 학습에 넣습니다. 다만 데이터가 많아지면 실제 로봇으로 학습한 IDM 라벨이 더 나았다는 결과는, 가상의 행동 공간이 실제 행동과 얼마나 맞는지가 결국 한계라는 뜻이기도 합니다.

**3. VLM을 얼리는 쪽으로 간 이유.** [OpenVLA]({% post_url 2026-10-21-openvla %})는 VLM의 비전 인코더까지 fine-tuning해야 성능이 났습니다. GR00T는 반대로 N1에서 언어 부분을, N1.5에서는 VLM 전체를 얼렸고, 오히려 지시 따르기가 크게 좋아졌습니다. 차이는 행동이 어디서 나오느냐입니다. OpenVLA는 LLM이 행동 토큰을 직접 내므로 VLM 전체가 바뀌어야 하지만, GR00T는 행동을 DiT가 만들고 VLM은 특징만 줍니다. 이때 VLM을 얼리면 로봇 데이터가 VLM의 언어·시각 지식을 망가뜨리지 못합니다. PI가 Knowledge Insulation으로 같은 문제를 푸는 것과 같은 방향입니다.

**4. 후학습의 망각.** 오른손 데이터로만 후학습하자 사전학습 때 할 수 있던 손 건네기를 잊은 관찰은 작지만 중요합니다. 범용 모델을 특정 작업에 맞출 때 무엇을 잃는지 측정하는 일은 아직 거의 다뤄지지 않았습니다.

**5. 공개의 가치.** 같은 시기의 [Helix]({% post_url 2026-10-19-vision-language-action-models %})는 블로그로만 공개됐지만, GR00T N1은 가중치, 데이터, 시뮬레이션 벤치마크를 함께 공개해 다른 연구자가 결과를 재현하고 비교할 수 있게 했습니다. 다만 평가가 짧은 탁상 작업과 자체 GR-1 작업 위주라, 긴 작업이나 다른 로봇에서의 성능은 더 지켜봐야 합니다.

## 7. 정리

| 항목 | 내용 |
|---|---|
| 구조 | Eagle-2 VLM(System 2, 중간 층 특징, 10Hz) + flow matching DiT(System 1, 120Hz), 몸별 MLP encoder·decoder, 2.2B |
| 행동 | 16 step chunk, 노이즈 제거 4 step, L40에서 63.9ms |
| 데이터 | 실제 로봇 → 시뮬레이션(78만 궤적)·생성 영상(88 → 827시간) → 사람 영상·웹, 행동 없는 영상은 latent action·IDM으로 라벨 |
| 결과 | 시뮬레이션 평균 45.0%(DP 33.4%), 실제 GR-1 76.8%(DP 46.4%), 데이터 10%로 DP 전체 데이터와 비슷 |
| N1.5 | VLM 고정·grounding 강화, FLARE, DreamGen. GR-1 지시 따르기 46.6% → 93.3% |
| 공개 | GR00T-N1-2B 가중치, 데이터, 시뮬레이션 벤치마크 |
