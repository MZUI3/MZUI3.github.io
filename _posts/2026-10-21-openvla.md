> [VLA 총정리 글]({% post_url 2026-10-19-vision-language-action-models %})의 다섯 번째 모델입니다. [RT-2]({% post_url 2026-10-20-rt-2 %})는 VLM이 행동 토큰을 내면 웹 지식이 로봇 제어로 넘어온다는 것을 보였지만, 모델은 공개되지 않았습니다. **OpenVLA**(*An Open-Source Vision-Language-Action Model*, Kim et al., CoRL 2024)는 같은 레시피를 **공개된 7B 모델**로 만들고, 연구실이 실제로 쓸 수 있도록 fine-tuning과 배포 비용까지 줄였습니다.

## 1. 문제: 닫힌 VLA, 알려지지 않은 fine-tuning

논문이 짚는 문제는 두 가지입니다.

1. **공개된 VLA가 없다.** RT-2와 RT-2-X(55B)는 비공개입니다. 공개된 범용 정책인 Octo나 RT-1-X는 언어 임베딩, 비전 인코더 같은 부품을 처음부터 학습하는 층으로 이어 붙인 구조라, 인터넷 사전학습의 이점을 덜 받습니다.
2. **새 로봇에 맞추는 법을 모른다.** 로봇 연구실마다 로봇과 작업이 다르므로 범용 모델을 각자의 환경에 fine-tuning해야 하는데, VLA를 효율적으로 fine-tuning하는 연구가 없었습니다.

## 2. 모델: Prismatic-7B 위에 행동 토큰

OpenVLA는 Prismatic-7B VLM을 fine-tuning해 만듭니다.

| 구성 | 내용 |
|---|---|
| 비전 인코더 (약 600M) | 이미지 패치를 **SigLIP**과 **DINOv2**에 각각 넣고 특징을 채널 방향으로 이어 붙임 |
| Projector | 2층 MLP로 시각 특징을 언어 모델 입력 공간으로 |
| 언어 모델 | **Llama 2 7B** |
| 입력 | 224×224 이미지 1장 + "What should the robot do to {task}? A:" |
| 출력 | 7차원 행동(위치 변화 3, 회전 변화 3, 그리퍼 1) = 행동 토큰 7개 |

SigLIP은 이미지와 텍스트를 맞추도록 학습해 **의미**를 잘 담고, DINOv2는 이미지만으로 자기지도 학습해 **공간적인 세부**를 잘 담습니다. 로봇 제어에는 둘 다 필요하다는 판단입니다.

행동은 RT-2처럼 차원마다 256개 구간으로 나누되, 구간 범위를 최솟값~최댓값이 아니라 **학습 데이터의 1~99% 분위수**로 잡아 드문 극단값 때문에 구간이 넓어지는 것을 막습니다. Llama 토크나이저는 새 토큰용 자리가 100개뿐이라, 가장 덜 쓰이는 **마지막 256개 토큰**을 행동 토큰으로 덮어씁니다. loss는 행동 토큰에만 cross entropy를 씁니다.

## 3. 데이터: Open X-Embodiment에서 고른 97만 궤적

**Open X-Embodiment(OXE)**는 여러 기관이 로봇 데이터를 같은 형식으로 모은 데이터셋으로, 당시 70개 넘는 데이터셋, 200만 개 넘는 궤적이었습니다. OpenVLA는 여기서

- 3인칭 카메라가 하나 이상 있고, 한 팔을 손끝 위치로 제어하는 조작 데이터만 남기고
- 데이터셋별 비중은 Octo의 가중치(다양한 데이터셋은 올리고 단조로운 데이터셋은 내림)를 따랐습니다.

결과는 **97만 개 궤적**입니다. DROID 데이터셋도 10% 비중으로 넣어 봤지만 행동 토큰 정확도가 계속 낮아, 학습 마지막 1/3에서는 뺐습니다. Bridge 데이터에서 모든 값이 0인 행동을 걸러 내는 등 정리 작업도 했습니다.

## 4. 설계 결정: 작게 실험해서 고른 것들

본 학습 전에 BridgeData V2만으로 작은 실험을 돌려 다음을 정했습니다.

- **Backbone**: IDEFICS-1, LLaVA, Prismatic을 비교했습니다. 여러 물체 중 지시한 물체를 집어야 하는 작업에서 LLaVA가 IDEFICS-1보다 35%p 높았고, Prismatic이 LLaVA보다 다시 약 10%p 높았습니다.
- **해상도**: 224와 384를 비교했는데 차이가 없었고, 384는 학습이 3배 느렸습니다. VLM 벤치마크에서는 해상도가 높을수록 좋은 것과 다른 결과입니다.
- **비전 인코더는 얼리지 않는다**: VLM을 학습할 때는 비전 인코더를 얼리는 쪽이 보통 더 좋습니다. 하지만 VLA에서는 **비전 인코더까지 fine-tuning해야** 훨씬 좋았습니다. 부록 실험에서 얼린 경우와 비교하면 성공률이 85% → 95%, 25% → 90%로 올랐습니다(두 가지 VLM 기준). 사전학습된 시각 특징에 정밀한 제어에 필요한 세부 공간 정보가 부족하다는 해석입니다.
- **Epoch**: LLM과 VLM은 데이터를 한두 번만 보지만, VLA는 행동 토큰 정확도가 95%를 넘을 때까지 실제 로봇 성능이 계속 올랐습니다. 최종 학습은 **27 epoch**입니다.
- **학습률**: 2e-5 고정, warmup 없음.

최종 학습에는 A100 64장으로 14일(21,500 A100-시간), 배치 2048이 들었습니다.

## 5. 실험

### 바로 쓰기: 두 종류의 로봇

학습 데이터에 있던 두 로봇으로 평가했습니다. 시각(새 배경·방해물), 동작(새 위치·방향), 물리(새 크기·모양), 의미(새 물체·지시·인터넷 개념) 일반화와 언어 지시 이해를 모두 시험합니다.

| 모델 | 크기 | BridgeData V2 (WidowX, 170회) | Google 로봇 (60회) |
|---|---|---|---|
| RT-1-X | 35M | 18.5 | 33.3 |
| Octo | 93M | 20.0 | 26.7 |
| RT-2-X | 55B | 50.6 | 78.3 |
| **OpenVLA** | 7B | **70.6** | **85.0** |

(성공률 %) 29개 작업 전체로 보면 OpenVLA가 7배 큰 RT-2-X보다 **16.5%p** 높습니다. RT-1-X와 Octo는 방해물이 있으면 엉뚱한 물체를 잡거나 팔을 허공에 휘젓기도 했습니다. 단, **의미 일반화**에서만은 RT-2-X가 더 좋았습니다. RT-2-X는 웹 데이터와 함께 co-fine-tuning해서 사전학습 지식을 더 잘 보존했지만, OpenVLA는 로봇 데이터로만 학습했기 때문입니다. 논문은 OpenVLA가 앞선 이유로 더 큰 데이터(97만 vs 35만 궤적), 꼼꼼한 데이터 정리, 두 비전 인코더의 결합을 꼽습니다.

### 새 로봇에 맞추기

학습 데이터에 없던 Franka 로봇 두 환경(5Hz 탁상형, 15Hz DROID형)에서 작업마다 시연 10~150개로 fine-tuning했습니다.

- **Diffusion Policy**(처음부터 학습)는 "당근을 그릇에 넣어"처럼 지시가 하나뿐인 좁은 작업에서 강했습니다.
- **Octo와 OpenVLA**(OXE 사전학습)는 여러 물체와 여러 지시가 섞인 다양한 작업에서 강했습니다.
- OpenVLA가 **평균 성능이 가장 높았고**, 모든 작업에서 50% 이상을 낸 유일한 방법이었습니다.
- OXE 사전학습 없이 Prismatic을 바로 fine-tuning한 **OpenVLA(scratch)**는 확연히 낮았습니다.

### LoRA: 1.4%만 학습해도 된다

| 방법 | 성공률 | 학습 파라미터 | GPU 메모리(배치 16) |
|---|---|---|---|
| 전체 fine-tuning | 69.7% | 7,188.1M | 163.3GB(GPU 2장) |
| 마지막 층만 | 30.3% | 465.1M | 51.4GB |
| 비전 인코더 고정 | 47.0% | 6,760.4M | 156.2GB(GPU 2장) |
| Sandwich(비전 인코더 + 임베딩 + 마지막 층) | 62.1% | 914.2M | 64.0GB |
| **LoRA (r = 32)** | **68.2%** | **97.6M** | 59.7GB |

여기서도 비전 인코더를 얼리면 성능이 크게 떨어집니다. LoRA는 모든 선형층에 작은 저랭크 행렬을 더해 그것만 학습하는 방법으로, 파라미터의 1.4%만 학습하면서 전체 fine-tuning과 비슷했습니다. 학습은 A100 한 장으로 10~15시간이면 끝나, 전체 fine-tuning(A100 8장, 5~15시간)보다 계산량이 8배 줄었습니다. rank는 성능에 거의 영향이 없어 32를 기본값으로 권합니다.

```python
import torch
import torch.nn as nn

class LoRALinear(nn.Module):
    """y = W x + (alpha / r) * B A x.  원래 가중치 W는 얼리고 작은 행렬 A, B만 학습한다 (Hu et al., 2021)."""
    def __init__(self, base: nn.Linear, r=32, alpha=16):
        super().__init__()
        self.base = base.requires_grad_(False)
        self.A = nn.Parameter(torch.randn(r, base.in_features) * 0.01)
        self.B = nn.Parameter(torch.zeros(base.out_features, r))      # 0으로 시작 → 처음에는 원래 층과 똑같다
        self.scale = alpha / r

    def forward(self, x):
        return self.base(x) + self.scale * (x @ self.A.T @ self.B.T)

torch.manual_seed(0)
layer = LoRALinear(nn.Linear(4096, 4096, bias=False))          # Llama 2 7B의 attention 투영 크기
trainable = sum(p.numel() for p in layer.parameters() if p.requires_grad)
total = sum(p.numel() for p in layer.parameters())
x = torch.randn(1, 4096)
print(f"층 하나: 학습 파라미터 {trainable:,} / 전체 {total:,} ({trainable / total:.1%})")
print("학습 전 출력이 원래 층과 같은가:", torch.allclose(layer(x), layer.base(x)))
print(f"OpenVLA 전체(논문): 97.6M / 7,188.1M = {97.6 / 7188.1:.1%}")
```

```text
층 하나: 학습 파라미터 262,144 / 전체 17,039,360 (1.5%)
학습 전 출력이 원래 층과 같은가: True
OpenVLA 전체(논문): 97.6M / 7,188.1M = 1.4%
```

$$B$$를 0으로 초기화하므로 학습 시작 시점의 모델은 사전학습된 OpenVLA와 정확히 같고, 학습이 진행되며 $$BA$$만큼만 달라집니다.

### 양자화: 4bit가 8bit보다 낫다?

| 정밀도 | 성공률(Bridge 8개 작업) | GPU 메모리 |
|---|---|---|
| bfloat16 | 71.3% | 16.8GB |
| int8 | 58.1% | 10.2GB |
| int4 | 71.9% | 7.0GB |

[4bit 양자화]({% post_url 2026-06-15-pruning-and-quantization %})는 메모리를 절반 이하로 줄이면서 성능을 유지했습니다. 이상한 것은 8bit입니다. 원인은 정확도가 아니라 **속도**였습니다. 8bit는 양자화 연산 오버헤드로 A5000에서 1.2Hz밖에 나오지 않아, 5Hz로 모은 학습 데이터와 로봇의 동역학이 달라졌습니다(4bit는 3Hz). 로봇이 매 행동을 기다려 주는 blocking 제어로 다시 재면 세 정밀도 모두 비슷했습니다. RTX 4090에서 bfloat16은 약 6Hz입니다.

### 무엇이 성능을 만들었나

| 모델 | 성공률(Bridge 8개 작업) |
|---|---|
| OpenVLA (OXE 학습) | 76.3% |
| OpenVLA-Bridge (Bridge 데이터만) | 45.6% |
| OpenVLA-Bridge-SigLIP (+ DINOv2 제거) | 40.6% |

OXE의 다양한 데이터를 빼면 30%p, DINOv2를 빼면 5%p가 떨어졌습니다. 데이터 다양성의 효과가 구조 변경보다 훨씬 큽니다.

## 6. 논문이 밝힌 한계

1. 이미지 한 장만 받습니다. 여러 카메라, 로봇 상태, 과거 관측을 쓰지 못합니다.
2. 약 6Hz로는 50Hz인 ALOHA 같은 정밀 양팔 작업을 할 수 없습니다. 논문은 action chunking과 speculative decoding을 해법 후보로 듭니다.
3. 성공률이 대체로 90% 미만이라 아직 믿고 쓸 수준은 아닙니다.
4. VLM 크기, 웹 데이터와의 공동 학습, 가장 좋은 시각 특징 같은 질문은 계산 자원이 부족해 답하지 못했습니다.

## 7. 해석

**1. 가장 큰 기여는 "공개"였다.** 모델, 학습 코드, fine-tuning 노트북, 원격 추론 서버까지 공개되면서 VLA가 몇몇 기업의 전유물에서 누구나 실험할 수 있는 대상이 됐습니다. 후속작 OpenVLA-OFT(2025)는 이 모델을 바탕으로 병렬 디코딩, action chunking, 연속 행동 출력(L1 회귀)을 더해 LIBERO 성공률을 76.5%에서 97.1%로, 행동 생성 속도를 26배로 올렸습니다. 한계 2번에 직접 답한 셈입니다.

**2. 행동이 LLM에서 나오면 VLM 전체가 바뀌어야 한다.** "비전 인코더를 얼리면 안 된다"는 발견은 흥미롭습니다. OpenVLA는 행동을 언어 모델의 토큰으로 내므로, 정밀한 위치 정보가 비전 인코더부터 LLM 끝까지 흘러야 합니다. 반면 나중에 나오는 [GR00T N1.5]({% post_url 2026-10-21-gr00t-n1 %})나 [SmolVLA]({% post_url 2026-10-22-smolvla %})는 VLM을 얼리고 별도의 action expert에 행동을 맡깁니다. 행동을 어디서 만드느냐에 따라 VLM을 얼릴지가 달라지는 셈입니다.

**3. 로봇 데이터만으로 학습하면 웹 지식이 줄어든다.** RT-2-X에 의미 일반화에서만 진 결과는, 웹 데이터와 함께 학습하는 co-training이 지식을 지키는 데 중요하다는 뜻입니다. 이 문제는 [π0.5]({% post_url 2026-10-22-pi05 %})의 이종 데이터 co-training과 이후의 Knowledge Insulation으로 이어집니다.

**4. 데이터 > 구조.** OXE를 빼면 30%p, 인코더 하나를 빼면 5%p가 떨어진 결과는 [RT-1]({% post_url 2026-10-20-rt-1 %})의 "다양성이 양보다 중요하다"와 같은 이야기입니다. 범용 로봇 정책의 성능은 결국 얼마나 다양한 로봇·장면·작업을 봤느냐가 좌우합니다.

**5. 토큰 방식의 마지막 정점.** OpenVLA는 "행동 = 256개 구간 토큰"이라는 RT 계열 방식을 공개 모델로 가장 잘 다듬은 결과입니다. 하지만 한 step씩, 한 토큰씩 내는 구조의 속도 한계는 그대로였고, 다음 장의 [π0]({% post_url 2026-10-21-pi0 %})는 행동을 연속값으로 한꺼번에 생성하는 쪽으로 방향을 바꿉니다.

## 8. 정리

| 항목 | 내용 |
|---|---|
| 모델 | Prismatic-7B: SigLIP + DINOv2 → MLP → Llama 2 7B, 행동 토큰 7개 |
| 데이터 | OXE에서 고른 97만 궤적, 27 epoch, A100 64장 × 14일 |
| 결과 | 29개 작업에서 RT-2-X(55B)보다 16.5%p 높음, 새 로봇 fine-tuning 평균 최고 |
| 실용성 | LoRA로 1.4%만 학습(A100 1장), 4bit 양자화로 7GB |
| 발견 | 비전 인코더 fine-tuning 필수, 해상도 224로 충분, 데이터 다양성이 가장 중요 |
