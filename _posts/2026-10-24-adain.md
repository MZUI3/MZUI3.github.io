> [Perceptual Losses]({% post_url 2026-10-24-perceptual-losses %})의 순전파 스타일 전이는 빠르지만 **스타일당 네트워크 하나**가 필요했습니다. 32개 스타일을 한 네트워크에 담는 조건부 IN(Dumoulin et al.)이 나왔지만 학습 때 본 스타일 밖으로는 못 나갔고, 패치 매칭으로 임의 스타일을 다루는 Chen & Schmidt의 style swap은 512×512에서 계산의 95%를 매칭에 써서 느렸습니다. **AdaIN**(Huang, Belongie, Cornell, ICCV 2017)은 "유연성 대 속도"의 딜레마를 한 줄의 수식으로 풉니다. 콘텐츠 특징을 인스턴스 정규화한 뒤 **스타일 특징의 채널별 평균과 표준편차로 되돌리는** 것입니다. 학습 가능한 파라미터가 없는 이 층 하나로 처음 보는 스타일을 256×256에서 56FPS로 전이합니다.

## 1. 관찰: 왜 인스턴스 정규화가 스타일 전이에 잘 듣는가

Ulyanov 등은 순전파 스타일 네트워크의 BN을 IN으로 바꾸기만 해도 크게 좋아진다는 것을 발견했고, 그 이유를 콘텐츠 이미지의 **대비(contrast) 불변성**으로 설명했습니다. 이 논문은 다른 가설을 세웁니다. 특징의 통계(Gram 행렬, 채널별 평균·분산)가 스타일을 담는다는 선행 연구가 있으므로, **IN은 각 샘플의 특징 통계를 정규화해 스타일을 지우는 연산**이라는 것입니다.

세 가지 학습 실험이 가설을 가릅니다. (a) 원본 이미지로 학습하면 IN이 BN보다 훨씬 빨리 수렴합니다. (b) 모든 학습 이미지의 휘도 히스토그램을 평활화해 **대비를 통일**해도 IN의 우위는 그대로입니다. 대비 가설로는 설명이 안 됩니다. (c) 사전학습 스타일 네트워크로 모든 이미지를 **같은 스타일로 미리 정규화**하면 IN의 우위가 거의 사라집니다. IN이 하던 일을 전처리가 대신한 것입니다. 결론: IN은 스타일 정규화입니다. BN은 배치 전체를 하나의 스타일 중심으로 정규화하므로 샘플마다 스타일이 남고, 조건부 IN의 아핀 파라미터 $$\gamma_s, \beta_s$$가 스타일을 바꿀 수 있는 이유도 **통계를 다른 값으로 정규화하기 때문**입니다.

## 2. 방법

### AdaIN

IN이 아핀 파라미터로 지정한 하나의 스타일로 정규화한다면, 그 파라미터를 **스타일 입력에서 계산**하면 임의 스타일이 됩니다.

$$
\text{AdaIN}(x, y) = \sigma(y)\left(\frac{x - \mu(x)}{\sigma(x)}\right) + \mu(y)
$$

$$\mu, \sigma$$는 채널별로 공간 위치에 대해 계산합니다. 학습 파라미터가 없고, IN과 같은 비용입니다. 붓질을 감지하는 채널이 있다면 스타일 이미지가 그 채널의 평균 활성을 높이고, AdaIN 출력은 같은 평균 활성을 가지면서 콘텐츠의 공간 구조는 유지합니다. 분산은 더 미묘한 스타일 정보를 옮깁니다.

### 구조

고정된 VGG-19의 relu4_1까지를 인코더 $$f$$로 써서 콘텐츠 $$c$$와 스타일 $$s$$를 인코딩하고, $$t = \text{AdaIN}(f(c), f(s))$$를 무작위 초기화한 디코더 $$g$$로 이미지 공간에 되돌립니다. 디코더는 인코더를 거울상으로 뒤집되 풀링을 최근접 업샘플링으로 바꾸고(체커보드 억제) 반사 패딩을 씁니다. 중요한 선택은 **디코더에 정규화 층을 두지 않는 것**입니다. IN은 각 샘플을 하나의 스타일로, BN은 배치를 하나의 스타일 중심으로 정규화하므로, 다양한 스타일을 생성해야 하는 디코더에는 둘 다 해롭습니다.

### 손실

같은 VGG로 $$\mathcal{L} = \mathcal{L}_c + \lambda \mathcal{L}_s$$를 계산합니다. 콘텐츠 손실은 출력의 relu4_1 특징과 **AdaIN 출력 $$t$$** 사이의 L2입니다(콘텐츠 이미지 특징이 아니라 $$t$$를 목표로 두면 수렴이 조금 빠르고 목표와도 일치). 스타일 손실은 Gram 행렬 대신 relu1_1, 2_1, 3_1, 4_1의 **채널별 평균과 표준편차의 L2**입니다. AdaIN이 옮기는 통계가 그것이므로 개념적으로 깔끔하고, Gram 손실과 결과는 비슷합니다. MS-COCO(콘텐츠)와 WikiArt(스타일) 각 8만 장, 짧은 변을 512로 리사이즈 후 256 크롭, Adam, 배치 8쌍으로 학습합니다.

### 런타임 제어

학습을 바꾸지 않고 추론 때 조절할 수 있습니다. **콘텐츠-스타일 트레이드오프**는 $$g((1 - \alpha) f(c) + \alpha\, \text{AdaIN}(f(c), f(s)))$$로 특징을 보간하면 되고($$\alpha = 0$$은 콘텐츠 재구성, 1은 완전 스타일화), **스타일 보간**은 여러 스타일의 AdaIN 출력을 가중합하며, **색 보존**은 스타일 이미지의 색을 콘텐츠에 먼저 맞추고, **공간 제어**는 마스크 영역마다 다른 스타일 통계를 적용합니다.

## 3. 코드로 보기: AdaIN과 IN의 동작

합성 특징 맵에서 AdaIN 출력의 통계가 스타일과 정확히 일치하고 공간 패턴은 콘텐츠와 일치하는지, 같은 콘텐츠의 두 스타일 버전이 IN 뒤에는 같아지는지(BN은 아닌지), 특징 보간으로 트레이드오프가 되는지 확인합니다.

```python
import torch
torch.manual_seed(0)
def stats(x): return x.mean(dim=(2, 3), keepdim=True), x.std(dim=(2, 3), keepdim=True) + 1e-5
def adain(x, y):
    mx, sx = stats(x); my, sy = stats(y); return sy * (x - mx) / sx + my
# "content" feature maps: a spatial pattern per channel; "style": channel-wise mean/std drawn per image
C, H, W = 8, 16, 16
pattern = torch.randn(1, C, H, W)
def stylize(pattern, seed):
    g = torch.Generator().manual_seed(seed)
    mu = torch.randn(1, C, 1, 1, generator=g) * 2; sd = torch.rand(1, C, 1, 1, generator=g) * 2 + 0.2
    return pattern * sd + mu
content = stylize(pattern, 1); style = stylize(torch.randn(1, C, H, W), 2)
out = adain(content, style)
mo, so = stats(out); ms, ss = stats(style)
print(f"AdaIN output matches the style statistics: max|mean diff| = {(mo-ms).abs().max():.1e}, max|std diff| = {(so-ss).abs().max():.1e}")
corr = torch.stack([torch.corrcoef(torch.stack([out[0, c].flatten(), content[0, c].flatten()]))[0, 1] for c in range(C)])
print(f"spatial pattern of each channel preserved: per-channel correlation with the content = {corr.min():.4f} .. {corr.max():.4f}")

# instance normalisation removes the style: IN of two differently styled versions of one content is identical
def IN(x): m, s = stats(x); return (x - m) / s
a, b = stylize(pattern, 3), stylize(pattern, 4)
print(f"IN(style A of content) vs IN(style B of content): max diff = {(IN(a)-IN(b)).abs().max():.1e}  -> IN = style normalisation")
# batch norm does not: statistics are shared across the batch
batch = torch.cat([a, b]); mb = batch.mean(dim=(0, 2, 3), keepdim=True); sb = batch.std(dim=(0, 2, 3), keepdim=True)
bn = (batch - mb) / sb
print(f"BN over the batch [A, B]: residual style difference between the two samples = {(bn[0]-bn[1]).abs().max():.2f}")

# runtime content-style trade-off by interpolating features
print()
for alpha in (0.0, 0.5, 1.0):
    t = (1 - alpha) * content + alpha * out
    print(f"alpha={alpha}: distance to content stats {((stats(t)[0]-stats(content)[0]).abs().mean()):.2f}, to style stats {((stats(t)[0]-ms).abs().mean()):.2f}")
```

```text
AdaIN output matches the style statistics: max|mean diff| = 2.4e-07, max|std diff| = 1.5e-05
spatial pattern of each channel preserved: per-channel correlation with the content = 1.0000 .. 1.0000
IN(style A of content) vs IN(style B of content): max diff = 1.1e-04  -> IN = style normalisation
BN over the batch [A, B]: residual style difference between the two samples = 3.80

alpha=0.0: distance to content stats 0.00, to style stats 1.83
alpha=0.5: distance to content stats 0.92, to style stats 0.92
alpha=1.0: distance to content stats 1.83, to style stats 0.00
```

- AdaIN 출력의 채널별 평균·표준편차는 스타일과 부동소수점 오차 수준으로 같고, 각 채널의 공간 패턴은 콘텐츠와 상관 1.0입니다. "통계는 스타일, 공간 배치는 콘텐츠"라는 분해가 수식 그대로 동작합니다.
- 같은 콘텐츠에 다른 스타일(채널별 스케일·이동)을 입힌 두 특징은 IN 뒤에 정확히 같아집니다. BN은 배치 통계를 쓰므로 두 샘플 사이의 스타일 차이가 남습니다. 논문의 Figure 1 해석을 가장 단순한 경우로 확인한 것입니다.
- $$\alpha$$를 0에서 1로 올리면 통계가 콘텐츠에서 스타일로 선형 이동합니다. AdaIN의 아핀 파라미터를 보간하는 것과 같습니다.

## 4. 실험

**품질.** 테스트 스타일은 학습 때 보지 않은 것입니다. 그런데도 결과는 스타일당 네트워크를 학습한 Ulyanov 등과 Gatys에 여러 예에서 필적하고, 일부(행 5)는 약간 뒤집니다. 속도·유연성·품질의 3자 트레이드오프가 있다는 것이 저자들의 입장입니다. 패치 매칭(Chen & Schmidt)은 대부분의 콘텐츠 패치가 대표성 없는 소수의 스타일 패치에 매칭되면 실패하는 반면, 전역 통계 매칭은 더 일반적입니다.

**정량.** IN 통계 기반 스타일 손실로 통일해 10개 스타일 × 50개 콘텐츠에서 재면, AdaIN의 콘텐츠·스타일 손실은 Ulyanov 등(스타일당 학습)보다 조금 높지만 비슷하고, 둘 다 Gatys의 50~100회 반복 수준입니다. 학습 때 못 본 스타일에서 이 정도면 일반화가 강하다는 뜻입니다.

**속도(Pascal Titan X, 스타일 인코딩 제외/포함).**

| 방법 | 256px | 512px | 스타일 수 |
|---|---|---|---|
| Gatys | 14.17s | 46.75s | ∞ |
| Chen & Schmidt | 0.171s (0.407) | 3.214s (4.144) | ∞ |
| Ulyanov | 0.011s | 0.038s | 1 |
| Dumoulin | 0.011s | 0.038s | 32 |
| AdaIN | 0.018s (0.027) | 0.065s (0.098) | ∞ |

임의 스타일 방법 중 Gatys보다 약 3자리, Chen & Schmidt보다 1~2자리 빠르고, 고정 스타일 순전파 방법과 비슷합니다. 비디오에서는 스타일 통계를 한 번만 계산하면 됩니다.

**Ablation.** AdaIN을 concatenation으로 바꾸면(Enc-Concat-Dec) 스타일 이미지의 윤곽이 출력에 비치고 콘텐츠 손실이 내려가지 않습니다. 디코더에 BN/IN을 넣으면 손실이 일관되게 높고 IN은 특히 나쁩니다. 디코더가 한 스타일로 정규화해 버리기 때문입니다.

## 5. 해석

**1. 설명이 먼저, 방법은 그 결과입니다.** 이 논문의 절반은 "IN은 왜 되는가"에 대한 실험적 설명이고, AdaIN은 그 설명에서 자연스럽게 나옵니다. 세 가지 대조 실험(원본, 대비 통일, 스타일 통일)의 설계가 깔끔해서, 방법보다 이 분석이 더 오래 인용됩니다.

**2. "스타일 = 채널 통계"가 생성 모델의 공용 인터페이스가 됐습니다.** StyleGAN은 잠재 코드에서 만든 통계를 AdaIN으로 주입해 스타일을 제어하고, [원샷 음성 변환]({% post_url 2026-10-24-hierarchical-speaker-svc %})은 화자 특성을 IN 통계로 정의합니다. [정규화 기법]({% post_url 2026-05-23-normalization %})이 학습 안정화 도구에서 **표현 조작 도구**로 바뀐 전환점입니다.

**3. 디코더에서 정규화를 빼는 선택이 역설적으로 중요합니다.** 정규화는 보통 넣을수록 좋다고 여기지만, 생성해야 할 출력의 다양성이 통계에 담겨 있다면 정규화가 그것을 지웁니다. StyleGAN2가 AdaIN의 통계 조작이 만드는 물방울 아티팩트를 해결하려고 가중치 변조로 바꾼 것도 같은 문제의 연장입니다.

**4. 한계는 전역 통계라는 점입니다.** 평균·분산은 1차·2차 통계뿐이라 공간적으로 복잡한 스타일(국소 패턴, 구도)은 옮기지 못하고, 결과의 질감이 평탄해지는 경향이 있습니다. WCT의 백색화-채색 변환, attention 기반 방법(SANet, AdaAttN), [StyTr²]({% post_url 2026-10-24-stytr2 %})가 이 지점을 공략합니다.

**5. 평가를 읽을 때 주의할 점.** 정량 비교는 손실 값이지 사람 평가가 아닙니다. 속도는 VGG 기반 인코더·디코더 때문에 고정 스타일 방법보다 조금 느린데, 저자들은 구조의 문제이지 방법의 한계가 아니라고 봅니다. 위 toy의 "스타일"은 채널별 아핀 변환으로 정의해 AdaIN에 유리한 설정이며, 실제 스타일은 통계만으로 다 담기지 않습니다.

## 6. 정리

| 항목 | 내용 |
|---|---|
| 관찰 | IN = 특징 통계 정규화 = 스타일 정규화(대비 통일·스타일 통일 대조 실험) |
| AdaIN | $$\sigma(y)\,(x - \mu(x))/\sigma(x) + \mu(y)$$, 파라미터 없음 |
| 구조 | 고정 VGG-19(relu4_1) 인코더 → AdaIN → 정규화 없는 디코더 |
| 손실 | 콘텐츠: AdaIN 출력과의 L2, 스타일: 4개 층의 평균·표준편차 L2 |
| 결과 | 미학습 스타일에 256px 56FPS, Gatys 대비 약 1,000배, 스타일당 학습 모델과 비슷한 손실 |
| 제어 | 특징 보간(콘텐츠-스타일), 스타일 보간, 색 보존, 마스크별 공간 제어를 추론 때 수행 |
