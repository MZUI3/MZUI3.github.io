> [VLA 총정리 글]({% post_url 2026-10-19-vision-language-action-models %})의 첫 모델입니다. **Gato**(*A Generalist Agent*, Reed et al., TMLR 2022)는 "[GPT]({% post_url 2026-07-01-transformer-decoder-to-gpt %})처럼 하나의 Transformer가 텍스트 밖의 일도 할 수 있을까?"를 묻습니다. 답은 **모든 데이터를 같은 토큰 열로 바꾸는 것**이었습니다. 가중치 한 벌로 Atari를 하고, 이미지를 설명하고, 대화하고, 실제 로봇팔로 블록을 쌓습니다.

## 1. 문제: 작업마다 따로 만드는 정책

강화학습과 로봇 제어에서는 보통 작업마다 정책을 새로 학습합니다. 여러 작업에 **같은 구조**를 쓰더라도 **가중치는 작업마다 다릅니다**. DQN이 Atari 게임마다 따로 학습되는 것처럼요. 논문은 이 둘을 분명히 구분합니다.

- **하나의 multi-task 구조**: 구조와 하이퍼파라미터는 같고, 가중치는 작업마다 다름
- **하나의 신경망**: 모든 작업에 **같은 가중치**를 씀

Gato가 시험하는 가설은 두 가지입니다. 첫째, 수백 개 작업을 가중치 한 벌로 해내는 범용 에이전트를 학습할 수 있다. 둘째, 이 에이전트는 적은 데이터로 새 작업에 적응할 수 있다. 언어 모델에서 본 scaling law처럼, 데이터·연산·파라미터를 늘리면 이 방향으로 계속 나아갈 수 있다는 기대가 깔려 있습니다.

## 2. 모든 것을 토큰 열로

### 토큰화

| 데이터 | 변환 | 토큰 번호 |
|---|---|---|
| 텍스트 | SentencePiece, 32,000개 subword | 0 ~ 31,999 |
| 이미지 | 겹치지 않는 16×16 패치, raster 순서 | 정수 토큰이 아니라 패치 자체를 임베딩 |
| 이산값(Atari 버튼 등) | 정수 그대로, row-major 순서 | 0 ~ 1,023 |
| 연속값(관절 각도, 토크 등) | mu-law로 [-1, 1]에 압축 → 균등한 1,024개 구간 | 32,000 ~ 33,023 |

연속값은 다음 식으로 압축합니다($$\mu = 100$$, $$M = 256$$). 압축 뒤 [-1, 1] 밖의 값은 잘라 냅니다. 행동은 이미 [-1, 1] 범위라 이 변환을 거치지 않습니다.

$$
F(x) = \text{sgn}(x)\,\frac{\log(\lvert x\rvert\mu + 1)}{\log(M\mu + 1)}
$$

0 근처의 작은 값은 넓게 펼치고 큰 값은 좁게 모읍니다. 같은 1,024개 구간이라도 작은 움직임을 훨씬 세밀하게 구분합니다.

```python
import numpy as np

MU, M, N_BINS, TEXT_VOCAB = 100, 256, 1024, 32000

def mu_law(x):
    return np.sign(x) * np.log(np.abs(x) * MU + 1.0) / np.log(M * MU + 1.0)

def inv_mu_law(y):
    return np.sign(y) * ((M * MU + 1.0) ** np.abs(y) - 1.0) / MU

def to_token(y):                                   # [-1, 1] → 1024개 구간 → [32000, 33024)
    return np.clip(((y + 1) / 2 * N_BINS).astype(int), 0, N_BINS - 1) + TEXT_VOCAB

def from_token(tok):
    return (tok - TEXT_VOCAB + 0.5) / N_BINS * 2 - 1        # 구간의 중심값

x = np.array([0.003, 0.03, 0.3, 3.0, 30.0])         # 관절 속도처럼 크기가 제각각인 값

tok_mu = to_token(np.clip(mu_law(x), -1, 1))
tok_uni = to_token(np.clip(x / M, -1, 1))            # 비교: [-256, 256]을 그냥 균등하게 1024개로
show = lambda v: "[" + ", ".join(f"{a:.4g}" for a in v) + "]"
print("mu-law 토큰:", tok_mu, "→ 복원", show(inv_mu_law(from_token(tok_mu))))
print("균등   토큰:", tok_uni, "→ 복원", show(from_token(tok_uni) * M))
```

```text
mu-law 토큰: [32525 32581 32685 32799 32915] → 복원 [0.003069, 0.02966, 0.3018, 2.978, 29.78]
균등   토큰: [32512 32512 32512 32518 32572] → 복원 [0.25, 0.25, 0.25, 3.25, 30.25]
```

같은 범위를 균등하게 나누면 구간 폭이 0.5라서 0.003, 0.03, 0.3이 모두 같은 토큰이 됩니다. mu-law를 거치면 다섯 값이 모두 다른 토큰이 되고, 상대 오차 몇 % 안에서 복원됩니다.

### 시퀀스 순서와 임베딩

토큰은 정해진 순서로 이어 붙입니다. 텍스트는 원래 순서, 이미지 패치는 raster 순서, 텐서는 row-major 순서입니다. 에이전트 데이터는 **[관측 토큰들] → [구분자] → [행동 토큰들]**이 한 timestep이고, 에피소드는 이 timestep들을 시간순으로 이은 것입니다.

임베딩은 모달리티마다 다릅니다.

- 텍스트·이산값·연속값 토큰: lookup table로 임베딩하고, **timestep 안에서의 위치**를 나타내는 학습 가능한 위치 인코딩을 더합니다.
- 이미지 패치: ResNet 블록 하나로 패치마다 벡터를 만들고, 이미지 안에서의 위치 인코딩을 더합니다.

## 3. 학습

### 행동과 텍스트만 맞히는 next-token prediction

언어 모델처럼 다음 토큰을 예측하되, **텍스트와 에이전트의 행동 토큰에만** loss를 줍니다. 이미지와 텍스트가 아닌 관측(관절 각도 등)은 입력으로만 쓰고 예측하지 않습니다.

$$
\mathcal{L}(\theta, \mathcal{B}) = -\sum_{b=1}^{\lvert\mathcal{B}\rvert}\sum_{l=1}^{L} m(b, l)\,\log p_\theta\big(s_l^{(b)} \mid s_1^{(b)}, \dots, s_{l-1}^{(b)}\big)
$$

$$m(b, l)$$은 $$l$$번째 토큰이 텍스트이거나 행동이면 1, 아니면 0입니다. 정답 행동을 그대로 따라 하는 **behavior cloning**을 시퀀스 모델로 한 셈입니다.

### 모델과 학습 규모

- 1.2B decoder-only Transformer: 24층, 임베딩 2048, FFN 은닉 크기 8196
- TPU v3 16×16 slice로 1M step, 배치 512, 시퀀스 길이 1024 토큰, 약 4일
- 한 배치에 여러 도메인의 시퀀스를 거의 균등하게 섞고, 크고 질 좋은 데이터는 비중을 높임

### 작업 이름 대신 시연으로 알려 주기

같은 로봇, 같은 관측 형식으로 여러 작업을 하면 모델은 지금 무슨 작업인지 알 수 없습니다. Gato는 one-hot 작업 ID를 주지 않고 **prompt**를 씁니다. 학습 때 배치의 25% 시퀀스 앞에 같은 작업의 다른 에피소드를 붙이는데, 그중 절반은 에피소드의 끝부분이라 "이런 결과를 만들어라"라는 목표 역할을 합니다. 평가 때는 성공한 시연 하나를 prompt로 줍니다.

### 데이터

| 구분 | 내용 | 배치 비중 |
|---|---|---|
| 제어 | 596개 작업, 6,300만 에피소드, 약 1.5조 토큰 | 85.3% |
| 비전·언어 | MassiveText, ALIGN, M3W, COCO 캡션, VQAv2 등 | 14.7% |

제어 데이터는 대부분 **시뮬레이션에서 최고 수준의 강화학습 에이전트가 학습하며 남긴 경험**입니다(Atari, DM Lab, Meta-World, BabyAI, DM Control 등). 전문가 return의 80% 이상인 에피소드만 골라 썼습니다. 실제 로봇 데이터는 Sawyer 로봇팔의 RGB 블록 쌓기 하나입니다.

## 4. 결과

### 시뮬레이션 제어

604개 작업 중 **450개 이상에서 전문가 점수의 50%**를 넘었습니다(0%는 무작위, 100%는 그 작업의 전문가).

- **Atari**: 23개 게임에서 평균적인 사람 이상, 11개는 사람의 2배 이상
- **BabyAI**: 거의 모든 레벨에서 전문가의 80% 이상, 가장 어려운 BossLevel은 75%
- **Meta-World**: 45개 작업 중 44개에서 50% 이상, 35개에서 80% 이상
- **DM Control**(상태 입력): 30개 중 21개에서 50% 이상

### 실제 로봇: RGB 블록 쌓기

빨간 블록을 파란 블록 위에 쌓는 작업입니다. 학습 때 보지 못한 모양의 블록 5세트로 평가하는 Skill Generalization에서 Gato는 평균 **50.2%**로, 이 작업 하나만 학습한 BC-IMP(49%)와 비슷했습니다. 수백 개 다른 작업을 함께 배우면서도 전용 모델만큼 한다는 점이 요점입니다.

### 텍스트

이미지 캡션과 대화도 하지만, 논문 스스로 대화가 자주 피상적이거나 사실과 다르다고 밝힙니다.

## 5. 분석

### 크기를 키우면 좋아진다

79M, 364M, 1.18B 세 크기를 비교하면, 같은 토큰 수를 학습했을 때 큰 모델일수록 성능이 꾸준히 높았습니다.

### 새 작업 적응: 무엇을 사전학습해야 하나

네 작업(cartpole.swingup, Meta-World assembly-v2, DM Lab 사과 모으기, Atari boxing)을 사전학습에서 빼고, 적은 시연으로 fine-tuning해 봤습니다(364M 모델).

| 작업 | 결과 |
|---|---|
| cartpole, assembly-v2 | 모든 데이터로 사전학습한 쪽이 가장 좋음. 텍스트·이미지만으로 사전학습하면 이득이 없거나 오히려 손해(assembly-v2) |
| DM Lab | 같은 도메인 데이터만으로도 충분. 텍스트·이미지 사전학습도 도움(자연스러운 영상이라서) |
| Atari boxing | 어떤 사전학습도 도움이 안 됐고, 처음부터 학습한 쪽이 더 좋음 |

### 로봇 fine-tuning

블록 쌓기에서는 10개 에피소드로 fine-tuning해도 전문가 수준을 회복했고, 100~1,000개에서는 전문가를 넘었습니다. 모델이 클수록 적은 데이터로 더 잘 적응했습니다. "파란 블록을 초록 블록 위에"라는 새 목표는 실제 로봇 시연 500개(2시간 45분)로 fine-tuning해 60%를 냈는데, 같은 데이터로 처음부터 학습한 BC는 0.5%(200번 중 1번)였습니다.

### 범용 vs 전용

Atari 51개 게임만 학습한 같은 크기(1.18B)의 **전용** 모델은 44개 게임에서 사람을 넘었습니다. 범용 Gato는 23개였습니다. 논문은 실제 로봇에서 실시간으로 돌리기 위해 **일부러 모델 크기를 제한했다**고 말합니다. 그래도 블록 쌓기 로봇의 20Hz 제어 주기를 맞추려면 평가 때 context를 1로 줄이고 행동 토큰을 한 번에 뽑아야 했고, 그러고도 RTX 3090에서 주기를 약 0.01초 넘겼습니다.

## 6. 해석: Gato가 남긴 것과 남긴 숙제

**남긴 것: "토큰화하면 다 같은 문제다."** 이미지, 텍스트, 버튼, 관절 토크가 한 시퀀스에서 같은 loss로 학습될 수 있음을 큰 규모로 처음 보였습니다. [Trajectory Transformer]({% post_url 2026-08-24-trajectory-transformer %})나 Decision Transformer가 한 작업 안에서 보여 준 시퀀스 모델링을 수백 개 작업과 여러 몸(embodiment)으로 넓힌 것입니다. 연속값을 구간으로 나눠 토큰으로 만드는 방식은 RT-1, RT-2, OpenVLA로 그대로 이어집니다.

**숙제 1: 지식이 행동으로 넘어가지 않았다.** 텍스트·이미지 사전학습은 제어 작업에 거의 도움이 안 됐습니다. Gato는 웹 데이터와 제어 데이터를 **처음부터 함께** 학습했고, 텍스트 비중도 15%가 안 됐습니다. 언어가 여러 몸을 잇는 공통 기반이 될 수 있다는 논문의 기대는, 웹 데이터로 **먼저 크게 학습한 VLM**에서 출발한 [RT-2]({% post_url 2026-10-20-rt-2 %})에서야 실현됩니다.

**숙제 2: 작업을 언어로 지시하지 않는다.** Gato는 작업을 성공 시연 prompt로 알아챕니다. "빨간 블록을 쌓아"라고 말로 지시하는 지금의 VLA와 다릅니다. 게다가 context가 1,024 토큰이라, 128×128 카메라 두 대면 이미지 토큰만 timestep당 128개입니다. 8 timestep도 다 들어가지 않으니, 20Hz 로봇이면 0.4초 남짓한 과거만 보는 셈입니다.

**숙제 3: 속도와 크기의 충돌.** 범용 모델은 전용 모델보다 약했고, 그 차이를 메울 방법인 "더 크게"는 실시간 제어와 부딪혔습니다. [RT-1]({% post_url 2026-10-20-rt-1 %})이 Gato를 비교 모델로 쓸 때 37M으로 줄여야 했던 것도 원래 크기의 로봇 추론이 1.9초나 걸렸기 때문입니다. 이 충돌은 이후 action chunking, System 1/2 구조로 이어지는 VLA의 큰 주제가 됩니다.

**숙제 4: 데이터의 출처.** 제어 데이터 대부분이 시뮬레이션 RL 에이전트의 경험이었습니다. 사람이 원격조작으로 모은 실제 로봇 데이터를 대량으로 쓰는 방향은 RT-1에서 시작됩니다.

## 7. 정리

| 항목 | 내용 |
|---|---|
| 핵심 아이디어 | 모든 모달리티를 하나의 토큰 열로, 가중치 한 벌로 604개 작업 |
| 행동 표현 | 연속값은 mu-law + 1,024개 구간, 이산값은 정수 토큰 |
| 학습 | 텍스트와 행동 토큰에만 loss를 주는 next-token prediction(behavior cloning) |
| 작업 지정 | 성공 시연을 prompt로 앞에 붙임 |
| 결과 | 450/604 작업에서 전문가의 50% 이상, 실제 블록 쌓기는 전용 모델과 비슷 |
| 한계 | 텍스트·이미지 지식이 제어로 거의 전이되지 않음, 짧은 context, 실시간 제어 때문에 제한된 크기 |
