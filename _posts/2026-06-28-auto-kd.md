> [DIST]({% post_url 2026-06-26-dist-kd %})처럼 좋은 증류 손실을 손으로 설계할 수도 있지만, 어떤 손실이 좋은지는 교사-학생 쌍과 작업에 따라 다릅니다. 같은 방법이라도 loss 가중치 하나에 성능이 크게 흔들리고, 교사가 바뀌면 순위가 뒤집힙니다. **Auto-KD**(Automated Knowledge Distillation via Monte Carlo Tree Search, Li, Dong et al., HKUST·NUDT, ICCV 2023)는 증류 설계 자체를 **탐색**합니다. 기존 방법들을 변환, 거리, 가중치의 조합으로 분해해 트리 모양의 탐색 공간을 만들고, Monte Carlo Tree Search로 탐색하며, 교사 추론 생략과 희소 학습 등으로 탐색 비용을 40배 줄였습니다.

## 1. 문제: 증류는 손으로 설계하고 손으로 조정한다

논문이 짚는 두 가지 문제입니다.

- **민감도**: ResNet-110 → ResNet-20(CIFAR-100)에서 같은 방법도 loss 가중치에 따라 정확도가 크게 달라지고, 교사를 바꾸면 방법 간 순위가 바뀝니다. 그래서 새 교사-학생 쌍마다 긴 튜닝이 필요합니다.
- **수동 설계**: 기존 distiller는 전문가의 손으로 만들어져 특정 작업이나 데이터셋에 맞춰져 있고, 새 상황으로 일반화가 제한됩니다.

자동 탐색이 답이지만 쉽지 않습니다. 증류는 하이퍼파라미터, 손실 함수, 변환 종류가 얽혀 있어 보통의 하이퍼파라미터 최적화보다 복잡하고, 가중치 공유(one-shot NAS)로 가속하기도 어려워 **다중 시도(multi-trial)** 탐색이 필요합니다.

## 2. 관찰: 분해되고, 조합되고, 단순화된다

기존 feature 증류 방법들을 분석해 세 가지를 발견합니다.

1. **분해 가능**: 대부분의 distiller는 변환 함수와 거리 함수의 조합입니다. SP와 ICKD는 거리가 비슷하고 변환이 다르며, ICKD와 CWD는 변환이 비슷하고 거리가 다릅니다.
2. **조합 가능**: attention 변환과 mask 변환에 multi-scale을 결합하면 추가 이득이 있고, SP의 sample-wise 변환에 G-L2 대신 KL을 쓰면 원래보다 좋습니다.
3. **단순화 가능**: L1 거리처럼 일관되게 나쁜 선택지는 공간에서 빼도 되고, loss 가중치는 네 가지 값 정도면 충분합니다.

효율 쪽에서는 교사 지식의 오프라인 저장, 학생의 희소 학습, 그리고 증류된 학생이 데이터 효율이 좋고 빨리 수렴한다는 성질이 탐색 가속에 쓸 수 있는 재료입니다.

## 3. 탐색 공간

증류 손실을 다음 꼴로 통일합니다.

$$
\mathcal{L}_{KD} = W_f \times D_f\big(T_f(f_S, f_T)\big) + W_p \times D_p(p_S / \tau,\ p_T / \tau)
$$

$$T_f$$는 feature 변환, $$D_f$$와 $$D_p$$는 feature와 logit의 거리, $$W_f$$, $$W_p$$는 가중치, $$\tau$$는 온도입니다. 핵심 연산을 **트리 구조**로 조직합니다.

| 종류 | 선택지 | 뜻 |
|---|---|---|
| Global $$T_f$$ | Attention / Mask / Original | $$\alpha \times f$$로 재정렬, $$M \in (0, 1)$$로 가리기, 그대로 |
| Intra-spatial $$T_f$$ | Multi-scale / Local / Original | $$H/2, H/4$$로 pooling, $$n \times n$$ 조각으로 분할, 그대로 |
| Inter-spatial $$T_f$$ | Sample / Channel / Original | $$N \times CHW$$(인스턴스 간 관계), $$C \times NHW$$(채널 간 관계), 그대로 |
| $$D_f$$ | G-L2 / KL / L2 | Gram 행렬의 정규화 차이, softmax 뒤 KL, 제곱 오차 |
| $$D_p$$ | KL / Pearson | logit 증류 거리([DIST]({% post_url 2026-06-26-dist-kd %})의 상관 거리 포함) |
| $$W_f$$ | 1, 5, 25, 50 | feature 손실 가중치 |
| $$W_p$$ | 0.1, 0.5, 1, 5 | logit 손실 가중치 |
| $$\tau$$ | 1, 2, 4, 8 | 온도 |

feature 크기는 pooling으로, 채널 수는 1×1 합성곱으로 맞춥니다. 확장 공간에는 embedding 증류용 Rényi 엔트로피, KL 앞의 logit 정규화, loss 가중치의 warm-up과 early-stop 옵션도 들어갑니다. 공간은 작고 균일하지만, 기존 SOTA 증류 방법들과 많은 새 조합을 모두 담습니다.

## 4. Monte Carlo Tree Search

탐색 공간을 Monte Carlo Tree로 모델링하면 **선택지 사이의 의존성**(어떤 변환이 어떤 거리와 잘 맞는지)을 잡을 수 있고, 해석과 안정성이 좋아집니다. 네 단계를 반복합니다.

1. **선택**: 루트부터 UCB로 자식을 고르며 내려갑니다.

$$
\nu(n_i) = \frac{R_i}{N_i} + C \sqrt{\frac{2 \ln N_b}{N_i}}
$$

$$R_i$$는 노드의 누적 보상, $$N_i$$와 $$N_b$$는 노드와 부모의 방문 수, $$C$$는 탐험 강도입니다.

2. **확장**: 선택된 노드에 자식을 추가합니다.
3. **시뮬레이션**: 새 노드부터 나머지 선택지를 무작위로 채워 말단 설정을 만들고, 그 distiller로 학생을 짧게 학습해 보상을 잽니다. 보상은 학생의 분류 손실과 교사-학생 표현의 CKA 유사도를 합친 것입니다.

$$
R = 1 - \big(\mathcal{L}_{CE}(p_S, Y) + \mathcal{L}_{CKA}(f_S, f_T)\big)
$$

4. **역전파**: 경로의 노드들에 보상과 방문 수를 더합니다.

## 5. 코드로 보기: 의존성이 있는 공간에서 MCTS가 무작위 탐색을 이기는 이유

변환 3단계 × 거리 × 가중치의 324개 설정을 가진 장난감 탐색 공간을 만들고, "attention + multi-scale"과 "sample-wise + KL"처럼 **조합에 따라 추가 이득이 있는** 보상 함수(학생을 실제로 학습하는 대신 표로 흉내)를 둡니다. 같은 평가 횟수에서 MCTS와 무작위 탐색이 찾은 최고 보상을 비교합니다.

```python
import math, random

random.seed(0)
# 1) 장난감 탐색 공간: 변환(3단계) × 거리 × 가중치. 트리의 깊이마다 하나씩 고른다
space = [["attention", "mask", "orig"], ["multiscale", "local", "orig"], ["sample", "channel", "orig"], ["G-L2", "KL", "L2"], [1, 5, 25, 50]]
def reward(cfg):
    """후보 distiller로 학생을 짧게 학습했을 때의 보상을 흉내 낸 표. 선택지 사이에 의존성이 있다."""
    g, intra, inter, dist, w = cfg
    r = 0.70
    r += {"attention": 0.02, "mask": 0.00, "orig": 0.01}[g]
    r += {"multiscale": 0.02, "local": -0.01, "orig": 0.0}[intra]
    r += 0.02 if (g == "attention" and intra == "multiscale") else 0.0     # attention + multi-scale 조합의 추가 이득
    r += {"sample": 0.01, "channel": 0.02, "orig": 0.0}[inter]
    r += {"G-L2": 0.01, "KL": 0.015, "L2": -0.01}[dist]
    r += 0.015 if (inter == "sample" and dist == "KL") else 0.0            # sample-wise 변환은 KL과 잘 맞는다
    r += {1: 0.0, 5: 0.01, 25: 0.015, 50: -0.02}[w]
    return r + random.gauss(0, 0.004)                                      # 학습의 무작위성

class Node:
    def __init__(self, depth, cfg): self.depth, self.cfg, self.children, self.N, self.R = depth, cfg, {}, 0, 0.0

def mcts(iters, C=0.05):
    root, best = Node(0, []), (-1, None)
    for _ in range(iters):
        node, path = root, [root]
        while node.depth < len(space):                                       # 선택: UCB로 자식을 고르고, 없으면 확장
            if len(node.children) < len(space[node.depth]):
                opt = [o for o in space[node.depth] if o not in node.children][0]
                node.children[opt] = Node(node.depth + 1, node.cfg + [opt]); node = node.children[opt]; path.append(node); break
            node = max(node.children.values(), key=lambda c: c.R / c.N + C * math.sqrt(2 * math.log(node.N) / c.N)); path.append(node)
        cfg = node.cfg + [random.choice(space[d]) for d in range(node.depth, len(space))]   # 시뮬레이션: 나머지는 무작위
        r = reward(cfg)
        if r > best[0]: best = (r, cfg)
        for n in path: n.N += 1; n.R += r                                    # 역전파
    return best

def random_search(iters):
    best = (-1, None)
    for _ in range(iters):
        cfg = [random.choice(s) for s in space]; r = reward(cfg)
        if r > best[0]: best = (r, cfg)
    return best

print(f"탐색 공간 크기: {math.prod(len(s) for s in space)}개 설정")
for iters in [30, 100, 300]:
    m = [mcts(iters)[0] for _ in range(20)]; rs = [random_search(iters)[0] for _ in range(20)]
    print(f"평가 {iters:3d}회: MCTS 최고 보상 {sum(m) / 20:.4f} | 무작위 탐색 {sum(rs) / 20:.4f}")
print("MCTS가 찾은 설정 예:", mcts(300)[1])
```

```text
탐색 공간 크기: 324개 설정
평가  30회: MCTS 최고 보상 0.8099 | 무작위 탐색 0.8007
평가 100회: MCTS 최고 보상 0.8207 | 무작위 탐색 0.8079
평가 300회: MCTS 최고 보상 0.8245 | 무작위 탐색 0.8126
MCTS가 찾은 설정 예: ['attention', 'multiscale', 'sample', 'KL', 25]
```

MCTS는 좋은 보상을 낸 앞쪽 선택(예: attention)의 서브트리를 더 자주 방문하므로, 그 아래에서 궁합이 맞는 뒤쪽 선택(multi-scale, sample + KL)을 빨리 찾습니다. 무작위 탐색은 조합의 의존성을 활용하지 못해 같은 평가 횟수에서 뒤처집니다. 논문이 CIFAR-100에서 무작위 탐색 대비 1~3% 높은 정확도를 보고한 것과 같은 구조입니다. 물론 실제 보상은 표 조회가 아니라 학생 학습이므로, 평가 한 번의 비용을 줄이는 것이 다음 문제입니다.

## 6. 탐색 가속

탐색 단계에서 후보 하나를 평가하는 비용을 네 가지로 줄입니다. ResNet-110 → ResNet-20, CIFAR-100, 2080Ti 한 장 기준입니다.

| 단계 | 파라미터(M) | 시간(GPU초) | 탐색 중 정확도 | 최종 정확도 |
|---|---|---|---|---|
| Baseline | 1.97 | 6,036 | 71.00 | 72.65 |
| + 오프라인 처리 | 0.27 (7.3배↓) | 4,654 (1.3배) | 70.82 | 72.65 |
| + 50% 희소 학습 | 0.13 (15.2배↓) | 3,816 (1.6배) | 70.66 | 72.61 |
| + 20% 부분집합 | 0.13 | 793 (7.6배) | 66.52 | 72.55 |
| + 20% early stop | 0.13 | 151 (**40배**) | 48.98 | 72.52 |

- **오프라인 처리**: 교사의 feature map을 한 번 저장해 두고 재사용합니다. 학습 때와 같은 augmentation을 적용해 공간 정렬을 맞춥니다. 교사 추론이 사라져 파라미터가 7배 줄어듭니다.
- **희소 학습**: 무작위 마스크로 학생 가중치의 50%를 0으로 두고 동적 전략으로 증류 이득을 보존합니다.
- **프록시 설정**: 증류된 학생은 데이터 효율이 좋고 빨리 수렴하므로, 데이터의 20%와 epoch의 20%만으로 후보의 질을 판단합니다.

탐색 중 정확도는 49%까지 떨어지지만 **최종 정확도는 72.65 → 72.52로 거의 같습니다**. 후보의 순위만 보존되면 되기 때문입니다. 탐색은 교사-학생 쌍마다 MCT 100회 반복입니다.

## 7. 확장과 탐색 결과에서 얻은 지침

**다층·다교사**: 여러 층이나 여러 교사의 feature를 함께 쓰면 가중치 조정이 어려워집니다. 정보 병목 이론에 기대어 **학습 없는 가중치**를 둡니다.

$$
\mathcal{L}_{\text{Auto-KD+TF}} = W_f \sum_{q \in Q} \mu_q \times D_f\big(T_f(f^q_S, f^q_T)\big),\qquad \mu_q = D_{\text{entropy}}(f^q_T) \times D_{CKA}(f^q_S, f^q_T)
$$

교사 feature의 엔트로피와 교사-학생 CKA 거리의 곱이 층별 가중치입니다.

**찾아낸 distiller들의 공통점**(논문 2.5절):

1. 채널별(channel-wise) 증류는 넓은 교사-학생에 좋습니다.
2. multi-scale은 교사-학생의 의미 격차가 클 때, 특히 downstream 작업에서 이득입니다.
3. mask는 격차가 큰 쌍에 맞지만 지식 손실이 생길 수 있습니다.
4. attention은 이종 구조, 특히 ViT에 유리합니다.
5. local 변환은 multi-label이나 국소 정보가 중요한 작업에 맞고 CIFAR에서는 평범합니다.
6. sample-wise는 여러 모델에 도움이 되지만 작업과 batch 크기에 영향을 받습니다.
7. KL은 범용성이 좋고, Pearson은 복잡한 작업에서 실용적입니다.
8. 온도 조정은 대부분 유용하고, feature 가중치의 최적값은 보통 1~25 사이입니다.

### ImageNet, ViT, 검출, 분할

- **ImageNet**: 전체에서 탐색하기 어려워 100클래스 부분집합(ImageNet-100)에서 탐색한 뒤 전체로 학습했습니다. ResNet-34→18 72.45%(KD 70.66, Review 71.61), ResNet-50→MobileNet 73.26%(Review 72.56).

- **COCO**: Faster R-CNN R50 38.4 → 42.4 AP, RetinaNet R50 37.4 → 41.1 AP로 FGD, MGD 같은 검출 전용 KD를 넘었습니다.
- **Cityscapes**: 3.1~3.7 mIoU 향상.

## 9. 해석

**1. "증류 방법"을 "증류 공간"으로 바꿨습니다.** SP, ICKD, CWD, AT, Review 같은 방법들이 사실은 몇 개의 부품 조합이라는 관찰이 이 논문의 출발점입니다. 그 관찰이 맞다면 새 방법을 논문으로 내는 대신 공간에서 찾으면 되고, 실제로 찾은 조합들이 손으로 만든 방법들을 넘었습니다. NAS가 구조 설계에 했던 일을 증류 설계에 한 것입니다.

**2. MCTS를 고른 이유는 의존성입니다.** 변환과 거리는 독립이 아닙니다. 위 예제처럼 attention 아래에서는 multi-scale이, sample-wise 아래에서는 KL이 좋습니다. 트리 탐색은 앞 선택에 조건부로 뒤 선택을 평가하므로 이런 궁합을 자연스럽게 잡습니다. 격자 탐색이나 독립 하이퍼파라미터 최적화는 그러지 못합니다.

**3. 가속 전략이 실용성을 결정합니다.** 다중 시도 탐색은 후보마다 학생을 학습해야 해서 비싼데, "순위만 보존되면 된다"는 통찰로 평가 비용을 40배 줄였습니다. 탐색 중 정확도가 49%여도 최종 정확도가 같다는 표가 그 통찰의 증거입니다. 교사 추론을 없애는 오프라인 처리는 어떤 증류 연구에서나 쓸 수 있는 기법입니다.

**4. 탐색 결과가 곧 설계 지침입니다.** 2.5절의 여덟 가지 관찰은 수백 번의 탐색에서 귀납된 것으로, "ViT에는 attention", "격차가 크면 multi-scale" 같은 지침은 탐색을 돌리지 않는 사람에게도 유용합니다. [DIST]({% post_url 2026-06-26-dist-kd %})의 Pearson 거리가 복잡한 작업에서 실용적이라는 관찰도 그중 하나입니다.

**5. 평가를 읽을 때 주의할 점.** 보상 함수의 CKA 항과 탐색 하이퍼파라미터($$C$$, 반복 100회)가 결과에 얼마나 민감한지는 다루지 않았습니다. ImageNet은 부분집합에서 탐색한 distiller를 전체에 옮긴 것이라 최적성이 보장되지 않습니다. 비교 방법들의 수치는 대부분 원 논문에서 가져왔고, 탐색 비용(100회 × 151초)은 작지만 0은 아닙니다.

## 10. 정리

| 항목 | 내용 |
|---|---|
| 문제 | 증류 성능이 하이퍼파라미터와 교사-학생 쌍에 민감하고 설계가 수동적 |
| 관찰 | 기존 distiller는 변환·거리·가중치로 분해되고, 조합되며, 단순화된다 |
| 탐색 공간 | Global/Intra/Inter-spatial 변환 × {G-L2, KL, L2} × 가중치 × (logit: KL/Pearson, 온도) |
| 탐색 | MCTS: UCB 선택 → 확장 → 무작위 시뮬레이션 → 역전파. 보상 = 1 − (CE + CKA 거리) |
| 가속 | 교사 feature 오프라인 저장, 50% 희소 학생, 20% 데이터, 20% epoch → 40배 빠르고 최종 정확도 유지 |
| 결과 | CIFAR-100 CNN 3~7%, ViT 2~13%, ImageNet ResNet-18 72.45%, COCO +3.7~4.0 AP, Cityscapes +3.1~3.7 mIoU |
