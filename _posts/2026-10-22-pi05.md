> [VLA 총정리 글]({% post_url 2026-10-19-vision-language-action-models %})의 아홉 번째 모델입니다. [π0]({% post_url 2026-10-21-pi0 %})는 빨래 개기처럼 정밀한 작업을 해냈지만, 대부분 학습 환경과 비슷한 곳에서 평가했습니다. **π0.5**(*a Vision-Language-Action Model with Open-World Generalization*, Physical Intelligence, 2025)의 목표는 **학습 때 한 번도 가 보지 않은 집**에 들어가 부엌과 침실을 정리하는 것입니다.

## 1. 문제: 데이터를 더 모으는 것만으로는 모든 집을 덮을 수 없다

물건 집기나 서랍 열기 같은 단순한 기술은 여러 환경에서 데이터를 모으면 새 환경으로도 일반화된다는 연구가 있습니다. 하지만 "부엌 치우기"처럼 여러 단계로 된 긴 작업은 가능한 상황이 너무 많아, 로봇 데이터를 무작정 늘려서는 다 덮을 수 없습니다. 실제로 새 환경으로 일반화를 보인 이전 연구들은 대부분 1분이 안 되는 단순한 작업이었고 성공률도 낮았습니다.

π0.5의 답은 **성격이 다른 여러 데이터에서 지식을 옮겨 오는 것**입니다. 대상 로봇의 데이터는 적어도, 다른 로봇, 다른 작업, 웹, 사람의 말에서 배운 것을 합치면 처음 보는 집에서도 일할 수 있다는 가설입니다.

## 2. 모델: 같은 모델이 먼저 말하고, 그다음 행동한다

### 두 단계 추론

π0.5는 π0와 같은 구조(PaliGemma VLM + 300M action expert)에서 출발하지만, 출력이 두 가지입니다. **텍스트**(다음 subtask, 질문의 답, 물체 위치)와 **행동**입니다. 행동 분포를 이렇게 나눕니다.

$$
\pi_\theta(a_{t:t+H}, \hat{\ell} \mid o_t, \ell) = \pi_\theta(a_{t:t+H} \mid o_t, \hat{\ell})\;\pi_\theta(\hat{\ell} \mid o_t, \ell)
$$

$$\ell$$은 "침실을 치워" 같은 전체 지시, $$\hat{\ell}$$은 모델이 스스로 생성한 "베개를 집어" 같은 subtask입니다. 먼저 현재 장면을 보고 다음 subtask를 텍스트로 생성하고(고수준), 그 subtask를 조건으로 action expert가 행동을 생성합니다(저수준). 두 단계를 **한 모델**이 합니다. 행동은 전체 지시가 아니라 subtask에만 의존한다는 점이 눈에 띕니다. 고수준 추론은 저수준보다 낮은 빈도로 돕니다.

로봇 상태(관절 각도 등)는 이산화해 텍스트 토큰으로 넣습니다.

### 학습은 토큰으로, 추론은 flow matching으로

FAST 논문에서 보였듯이 행동을 압축된 이산 토큰으로 바꾸면 VLA 학습이 훨씬 빠릅니다. 반면 토큰을 하나씩 생성하는 추론은 느려 실시간 제어에 맞지 않습니다. π0.5는 둘을 함께 씁니다.

$$
\mathcal{L} = \underbrace{H\big(x_{1:M},\, f^{\ell}_\theta(o_t, \ell)\big)}_{\text{텍스트 + FAST 행동 토큰의 cross entropy}} + \alpha\,\underbrace{\big\lVert \omega - a_{t:t+H} - f^{a}_\theta(a^{\tau}_{t:t+H}, o_t, \ell) \big\rVert^2}_{\text{action expert의 flow matching}}
$$

($$\omega$$는 노이즈, 논문 표기) FAST 토큰과 flow matching 쪽 행동 토큰은 attention mask로 서로 보지 못하게 합니다.

- **사전학습**($$\alpha = 0$$, 280k step): 모든 데이터를 토큰으로 바꿔 보통의 VLM처럼 next-token prediction만 합니다. 단순하고 빠르게 학습됩니다.
- **후학습**($$\alpha = 10$$, 80k step): 무작위로 초기화한 action expert를 붙여 flow matching을 함께 학습합니다.
- **추론**: subtask 텍스트를 생성한 뒤, 이를 조건으로 10 step 노이즈 제거해 50Hz action chunk를 냅니다.

### FAST: 행동 chunk를 압축하는 토큰화

FAST(Pertsch et al., 2025)는 행동 chunk를 관절마다 **DCT(이산 코사인 변환)**로 주파수 성분으로 바꾸고, 배율을 곱해 반올림한 뒤, 저주파 성분부터 펼쳐 **BPE**로 묶습니다. 부드러운 행동은 저주파 몇 개에 정보가 몰리고 나머지는 0이 되므로 크게 압축됩니다. 아래는 이 과정을 작게 재현한 것입니다.

```python
import numpy as np
from collections import Counter
from scipy.fft import dct, idct

rng = np.random.default_rng(0)
T, DIMS, SCALE = 50, 7, 10                               # 50Hz x 1초 chunk, 관절 7개, 반올림 전 배율

def random_chunk():                                      # 부드럽게 움직이는 (50, 7) 행동 chunk
    t = np.linspace(0, 1, T)[:, None]
    f, p, a = rng.uniform(0.2, 1.0, DIMS), rng.uniform(0, 2 * np.pi, DIMS), rng.uniform(0.2, 0.8, DIMS)
    return a * np.sin(2 * np.pi * f * t + p)

def to_symbols(chunk):                                   # 관절마다 시간축 DCT → 반올림 → 저주파부터 펼치기
    return list(np.round(dct(chunk, axis=0, norm="ortho") * SCALE).astype(int).flatten())

def merge(seq, pair, new):                               # seq에서 pair를 새 기호 하나로 합친다
    out, i = [], 0
    while i < len(seq):
        if i + 1 < len(seq) and (seq[i], seq[i + 1]) == pair:
            out.append(new); i += 2
        else:
            out.append(seq[i]); i += 1
    return out

train = [to_symbols(random_chunk()) for _ in range(100)]
merges = []
for k in range(150):                                     # BPE: 가장 자주 붙어 나오는 쌍을 새 토큰으로
    pairs = Counter(p for s in train for p in zip(s, s[1:]))
    pair = pairs.most_common(1)[0][0]
    merges.append((pair, f"m{k}"))
    train = [merge(s, pair, f"m{k}") for s in train]

test = [random_chunk() for _ in range(20)]
lengths = []
for chunk in test:
    seq = to_symbols(chunk)
    for pair, new in merges:
        seq = merge(seq, pair, new)
    lengths.append(len(seq))
recon = idct(np.round(dct(test[0], axis=0, norm="ortho") * SCALE) / SCALE, axis=0, norm="ortho")
print(f"step·관절마다 토큰 1개: {T * DIMS}개")
print(f"DCT + 반올림 + BPE 후: 평균 {np.mean(lengths):.0f}개 (chunk 20개)")
print(f"반올림으로 생긴 복원 오차: 최대 {np.abs(recon - test[0]).max():.3f}")
```

```text
step·관절마다 토큰 1개: 350개
DCT + 반올림 + BPE 후: 평균 37개 (chunk 20개)
반올림으로 생긴 복원 오차: 최대 0.035
```

1초 분량 chunk가 토큰 350개에서 37개 정도로 줄었습니다. step마다 토큰을 하나씩 만들면 이웃한 토큰이 거의 같아 "앞 토큰 베끼기"만으로 loss가 낮아지는데, 압축된 토큰은 하나하나가 정보를 많이 담아 next-token prediction이 제대로 된 학습 신호가 됩니다. FAST 논문은 이 방식으로 학습한 π0-FAST가 π0와 비슷한 성능을 내면서 학습은 최대 5배 빨랐다고 보고합니다.

## 3. 데이터: 대상 로봇의 데이터는 일부일 뿐

| 데이터 | 내용 | 사용 단계 |
|---|---|---|
| **MM** 이동 로봇 | 약 100곳의 집에서 모은 가정용 작업 약 400시간 | 사전·후학습 |
| **ME** 고정형 로봇 | 한 팔·두 팔 로봇을 여러 집의 탁자 등에 고정해 모은 데이터. 옮기기 쉬워 더 많은 집에서 모음 | 사전·후학습 |
| **CE** 실험실 데이터 | 여러 종류의 로봇으로 실험실에서 모은 다양한 작업(식탁 치우기, 셔츠 개기, 커피콩 갈기 등) + OXE | 사전학습 |
| **HL** 고수준 예측 | 로봇 데이터에 subtask("이불을 정리해", "베개를 집어")를 사람이 주석하고 관련 물체 위치도 라벨로 붙임. 위치 → subtask → 행동 순으로 예측 | 사전·후학습 |
| **WD** 웹 데이터 | 이미지 캡션, VQA, 물체 위치 찾기(실내 장면과 가정용 물건 추가) | 사전·후학습 |
| **VI** 말로 하는 지시 | 전문가가 학습된 로봇에게 실시간으로 subtask를 하나씩 말해 작업을 시킨 기록 | 후학습 |

첫 학습 단계의 예시 중 **97.6%**가 가정용 이동 로봇(MM)이 아닌 다른 출처에서 왔습니다. 행동은 데이터셋마다 1~99% 분위수로 [-1, 1]에 정규화하고, 관절 각도 제어인지 손끝 위치 제어인지를 프롬프트에 표시합니다.

**VI**가 흥미롭습니다. 고수준 정책을 위한 "시연"을 사람이 로봇을 손으로 움직여서가 아니라 **말로** 보여 주는 셈입니다. "컵을 싱크대에 넣어", "베개를 침대에 놓아"처럼 지시를 하나씩 내려 학습된 저수준 정책이 실행하게 하면, 좋은 subtask 순서의 예시가 쌓입니다.

로봇은 두 종류의 이동형 양팔 로봇입니다. 6자유도 팔 2개, 손목 카메라 2개, 앞뒤 카메라, 전방향 바퀴, 몸통 승강 장치가 있어 상태·행동이 18~19차원입니다. 모델이 팔, 그리퍼, 몸통의 목표 위치와 바퀴 속도를 50Hz로 내면 단순한 PD 제어기가 따라갈 뿐, 경로 계획이나 충돌 검사 없이 **이동과 조작 모두 end-to-end**입니다. 고수준 추론에는 카메라 4대를, 저수준에는 손목과 앞 카메라를 씁니다.

## 4. 실험: 모두 처음 보는 환경에서

모든 평가는 학습에 없던 환경에서 했습니다. 정량 비교는 재현 가능한 모형 집(mock home)에서, 최종 평가는 실제 집 세 곳에서 했습니다.

### 실제 집

학습에 없던 세 집의 부엌과 침실에서 "서랍에 물건 넣기", "빨래 바구니에 옷 넣기", "싱크대에 그릇 넣기"를 시켰습니다. 2~5분 걸리는 여러 단계 작업을, 사람은 "그릇을 싱크대에 넣어" 같은 지시만 주고 모델이 "컵을 집어", "숟가락을 집어" 같은 다음 단계를 스스로 정하며 꾸준히 해냈습니다. 모형 집에서의 성능이 실제 집 성능을 잘 대표한다는 것도 확인했습니다.

### 학습 환경 수를 늘리면

이동 로봇 데이터의 환경 수를 3, 12, 22, 53, 82, 104곳으로 바꿔 가며(데이터 양은 맞춤) 평가했습니다.

- 환경이 많을수록 네 가지 작업(싱크대, 서랍, 빨래 바구니, 침대 정리)의 성능이 좋아졌습니다.
- **104곳으로 학습한 모델은 시험 집 자체의 데이터로 학습한 모델과 비슷했습니다.** 시험 환경을 한 번도 보지 않고도 그 환경을 직접 본 모델만큼 한다는 뜻입니다.
- 다만 다른 데이터(ME, CE, HL, WD) 없이 이동 로봇 데이터만으로 학습하면, 시험 집의 데이터를 써도 성능이 크게 떨어졌습니다.
- 지시한 물체를 고르는 비율도 환경 수와 함께 올랐고, 학습에 있던 종류의 물체가 처음 보는 종류보다 빨리 좋아졌습니다.

### 무엇이 중요했나

- **다른 로봇 데이터(ME, CE)**: 둘 중 하나만 빼도 크게 떨어지고, 둘 다 빼면 더 떨어졌습니다. 다른 환경의 데이터(ME)와 다른 작업의 데이터(CE) 모두에서 지식이 옮겨 옵니다.
- **웹 데이터(WD)**: 전체 작업 점수에는 큰 차이가 없었지만, **처음 보는 종류의 물체**를 지시대로 고르는 능력과 고수준 추론에서 크게 중요했습니다.
- **π0, π0-FAST+Flow와 비교**: 같은 로봇 데이터로 학습한 π0, 그리고 π0.5와 같은 하이브리드 학습을 하되 HL·WD를 뺀 π0-FAST+Flow보다 π0.5가 크게 좋았습니다. π0를 300k step까지 더 학습시켜도 마찬가지였습니다.

### 고수준 추론은 얼마나 중요한가

| 방법 | 결과 |
|---|---|
| **π0.5** (고수준 + 저수준) | 가장 좋음, 사람이 subtask를 직접 지시한 경우보다도 좋음 |
| implicit HL (subtask 데이터로 학습은 했지만 추론 때 subtask를 생성하지 않음) | 두 번째 |
| no VI (말로 하는 지시 데이터 제거) | 크게 나빠짐(VI는 고수준 데이터의 약 11%뿐) |
| no WD (웹 데이터 제거) | 크게 나빠짐 |
| no HL (subtask 데이터를 학습에도 쓰지 않음) | 크게 나빠짐 |
| GPT-4를 고수준 정책으로 | 가장 나쁨 |

## 5. 논문이 밝힌 한계

- 여전히 실수합니다. 낯선 서랍 손잡이나 로봇이 열기 어려운 캐비닛, 로봇 팔이 닦아야 할 얼룩을 가리는 상황에 약합니다.
- 고수준 추론이 쉽게 흐트러져, 물건을 넣다가 서랍을 여러 번 열고 닫기도 합니다.
- 비교적 단순한 지시만 처리하고, 문맥(기억)이 짧아 방을 옮겨 다니거나 물건 위치를 기억해야 하는 작업은 어렵습니다.

## 6. 해석

**1. 다양성의 축이 "데이터 출처"로 넓어졌다.** [RT-1]({% post_url 2026-10-20-rt-1 %})과 [OpenVLA]({% post_url 2026-10-21-openvla %})는 로봇 데이터 안에서 다양성이 양보다 중요하다고 보였습니다. π0.5는 다양성을 **다른 몸, 다른 작업, 웹, 사람의 말**로 넓힙니다. 대상 로봇 데이터는 2.4%에 불과했지만, 104곳의 환경과 다른 출처의 데이터를 합치자 시험 환경을 직접 본 모델만큼 일반화했습니다.

**2. subtask 예측은 "생각"이면서 학습 신호다.** 같은 모델이 subtask를 먼저 말하고 행동하는 구조는 [Thought Cloning]({% post_url 2026-10-01-thought-cloning %})의 "생각 → 행동"을 VLA 하나에 넣은 셈입니다. 그런데 추론 때 subtask를 생성하지 않아도(implicit HL) 두 번째로 좋았습니다. subtask를 맞히는 학습 자체가 모델의 표현을 "작업을 단계로 이해하는" 방향으로 바꾼다는 뜻입니다.

**3. 사람보다 나은 고수준 지시.** 모델이 직접 만든 subtask가 사람이 내린 subtask보다 나았던 결과는 처음엔 이상해 보입니다. 하지만 모델의 subtask는 자기 저수준 정책이 잘 수행하는 표현과 순서로 학습된 것입니다. 사람의 지시는 의미상 맞아도 저수준 정책이 익숙하지 않은 방식일 수 있습니다. 두 단계가 같은 모델 안에서 함께 학습될 때의 이점입니다. 반대로 로봇 데이터로 맞추지 않은 GPT-4가 가장 나빴다는 것은, 고수준 계획도 로봇의 능력에 맞춰 학습되어야 한다는 뜻입니다.

**4. 웹 데이터는 손이 아니라 눈과 머리를 키운다.** 웹 데이터를 빼도 전체 작업 점수는 비슷했지만, 처음 보는 물체와 고수준 추론에서 크게 떨어졌습니다. [RT-2]({% post_url 2026-10-20-rt-2 %})에서 본 "웹 지식은 무엇을 어디로, 로봇 데이터는 어떻게"라는 분업과 같은 그림입니다.

**5. "빠르게 학습하고, 빠르게 실행한다".** 사전학습은 토큰으로, 후학습부터 flow matching을 붙이는 방식은 학습 효율과 추론 속도를 함께 잡습니다. 같은 팀은 이후 action expert의 기울기가 VLM으로 흐르지 않게 막는 **Knowledge Insulation**을 내놓아 이 방식을 더 다듬었고, 이것이 [π0.6]({% post_url 2026-10-23-pi-star-0-6 %})의 학습 방법이 됩니다. 2025년 9월에는 π0.5 가중치도 openpi로 공개됐습니다.

**6. 평가를 읽을 때 주의할 점.** 모형 집과 실제 집 세 곳에서, 작업 단계별 진행률로 채점한 결과입니다. 결과가 대부분 그래프로 제시되고 작업도 PI가 정의한 것이라, 다른 모델과 숫자를 직접 비교하기는 어렵습니다.

## 7. 정리

| 항목 | 내용 |
|---|---|
| 목표 | 학습 때 본 적 없는 집에서 길고 여러 단계로 된 정리 작업 |
| 구조 | π0 기반(PaliGemma + action expert), 같은 모델이 subtask 텍스트 → 행동 순으로 생성 |
| 학습 | 사전학습은 FAST 토큰 next-token prediction(280k step), 후학습에 flow matching action expert 추가(80k step) |
| 데이터 | 이동 로봇 400시간(약 100곳) + 고정형 로봇, 실험실 데이터, subtask 주석, 웹 데이터, 말로 하는 지시. 97.6%가 다른 출처 |
| 결과 | 실제 집 세 곳에서 2~5분 작업 수행, 104곳 학습 시 시험 환경 데이터로 학습한 모델과 비슷 |
| 핵심 발견 | 다른 로봇 데이터 필수, 웹 데이터는 새 물체·고수준 추론에 중요, 모델 자신의 subtask가 사람 지시보다 나음 |
