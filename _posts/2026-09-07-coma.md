> [QMIX]({% post_url 2026-07-15-qmix %})가 Q-Learning 기반으로 멀티에이전트 협력을 다뤘다면, **COMA(Counterfactual Multi-Agent Policy Gradients)**(Foerster et al., AAAI 2018)는 **Actor-Critic** 기반입니다. 팀 전체가 하나의 보상을 받을 때 "**그 보상에 내가 얼마나 기여했는가**"를, 내 행동만 바꿔 보는 **반사실적(counterfactual)** 비교로 계산합니다.

## 1. 멀티에이전트 환경의 특징

- **부분 관측**: 각 에이전트는 전체가 아니라 자기 주변만 봄
- **관측 공유 없음**: 에이전트끼리 관측을 공유하지 않음
- **팀 보상**: 보상은 개인이 아니라 **팀 단위**로 하나만 주어짐
- **Joint action**: 에이전트가 $$n$$명이고 각자 행동이 $$\lvert U\rvert$$개면 조합은 $$\lvert U\rvert^n$$개. 예: 상·하·좌·우 4개 행동, 에이전트 5명이면 1,024개

### Credit Assignment 문제

팀이 승리해 보상을 받았을 때, 공격한 에이전트와 가만히 있던 에이전트가 **같은 보상**을 받습니다. 그러면 각자는 자기 행동이 좋았는지 나빴는지 알 수 없습니다. 특히 **자신을 희생해 팀을 돕는 행동**의 가치를 계산하기 어렵습니다.

## 2. 이전 방법

### IQL (Independent Q-Learning)

각 에이전트가 자기 부분 관측으로 독립적으로 Q-learning을 합니다. 에이전트 수가 많거나, 역할이 복잡하거나, 에이전트끼리 역할이 다를 때 **충돌**이 생깁니다. 다른 에이전트도 같이 학습하며 변하므로 환경이 non-stationary해집니다.

### IAC (Independent Actor-Critic)

각 에이전트가 독립적인 actor-critic을 가집니다. **파라미터를 공유**하면 학습 속도가 빨라지지만, critic이 **자기 행동만** 보고 joint action을 보지 않아 에이전트 간 정보 공유가 어렵습니다.

## 3. Actor-Critic 복습

- **Critic만 쓰는 방식(critic-only)**: Q-learning처럼 가치 함수를 최적화하고, 정책(ε-greedy 등)은 critic에서 바로 유도
- **Actor만 쓰는 방식(actor-only)**: Policy gradient처럼 가치 함수 없이 정책 확률을 직접 학습. 가치는 Monte Carlo로 추정
- **Actor-Critic**: 둘을 동시에 학습
  - **Actor**: 정책 $$\pi(u \mid \tau)$$ — 상태에서 행동을 결정
  - **Critic**: 가치 함수 — 상태(와 행동)에서 보상을 추정

## 4. COMA의 세 가지 아이디어

1. **Centralised Critic, Decentralised Actors**
2. **Counterfactual Baseline**
3. Counterfactual baseline을 **한 번의 forward pass**로 효율적으로 계산하는 critic 구조

### (1) Centralised Critic & Decentralised Policy

- **Actor(정책)**: 각 에이전트는 자기 관측 이력 $$\tau^a$$만 보고 행동 $$\pi^a(u^a \mid \tau^a)$$. 실행할 때 필요한 것은 이것뿐
- **Critic**: 학습할 때만 쓰므로, **전역 상태 $$s$$와 모든 에이전트의 joint action $$\mathbf{u}$$**를 볼 수 있음

$$
Q(s, \mathbf{u})
$$

[QMIX]({% post_url 2026-07-15-qmix %})와 같은 **CTDE**(Centralised Training, Decentralised Execution) 틀입니다.

### (2) Counterfactual Baseline

#### 단순한 방법의 문제

Centralised critic의 TD error로 각 actor를 업데이트하면 모든 에이전트가 **같은 학습 신호**를 받아, credit assignment가 해결되지 않습니다.

#### Difference Reward

"내가 기본 행동(default action) $$c^a$$를 했다면 팀 보상이 얼마였을까?"와 비교하는 아이디어입니다.

$$
D^a = r(s, \mathbf{u}) - r\big(s, (\mathbf{u}^{-a}, c^a)\big)
$$

($$\mathbf{u}^{-a}$$: 에이전트 $$a$$를 제외한 나머지의 행동)

하지만 두 가지 문제가 있습니다.

- **기본 행동을 무엇으로 정할지** 사람이 정해야 함
- 반사실적 보상을 구하려면 **추가 시뮬레이션**이 필요함

#### COMA의 해결

Critic $$Q(s, \mathbf{u})$$를 학습해 두면, 시뮬레이션 없이 **critic으로** 반사실적 가치를 계산할 수 있습니다. 그리고 기본 행동 하나 대신 **내 정책의 모든 행동에 대한 기댓값**을 baseline으로 씁니다.

$$
A^a(s, \mathbf{u}) = Q(s, \mathbf{u}) - \sum_{u'^a}\pi^a(u'^a \mid \tau^a)\,Q\big(s, (\mathbf{u}^{-a}, u'^a)\big)
$$

- 앞 항: **실제로 한 행동**의 가치
- 뒤 항: 다른 에이전트의 행동은 **그대로 두고**, 나만 행동을 바꿨을 때의 **평균 가치**

이 차이가 "다른 에이전트가 한 일과 별개로 **내 행동이 팀에 더한 가치**"입니다. 각 에이전트는 이 advantage로 정책을 업데이트합니다.

$$
g = \mathbb{E}_\pi\Big[\sum_a\nabla_\theta\log\pi^a(u^a \mid \tau^a)\,A^a(s, \mathbf{u})\Big]
$$

Baseline이 자기 행동에 의존하지 않으므로, 기울기의 **기댓값은 바뀌지 않고 분산만 줄어듭니다.**

### (3) 한 번의 Forward Pass로 계산

Baseline을 구하려면 에이전트 $$a$$의 모든 행동 $$u'^a$$에 대해 Q를 계산해야 합니다. Joint action 전체를 입력으로 받으면 $$\lvert U\rvert$$번 forward해야 하니, critic 구조를 바꿉니다.

- **입력**: 전역 상태, 에이전트 $$a$$의 관측, **다른 에이전트들의 행동** $$\mathbf{u}^{-a}$$, 에이전트 id
- **출력**: 에이전트 $$a$$의 **각 행동에 대한 Q 값** $$\lvert U\rvert$$개

그러면 한 번의 forward로 $$Q(s, (\mathbf{u}^{-a}, u'^a))$$를 모든 $$u'^a$$에 대해 얻습니다.

```python
import torch

def coma_advantage(critic, policy_probs, state, obs_a, u_minus_a, agent_id, u_a):
    """critic: (state, obs_a, u_minus_a, agent_id) -> (B, |U|) 각 행동의 Q
    policy_probs: (B, |U|) = π^a(·|τ^a)"""
    q_all = critic(state, obs_a, u_minus_a, agent_id)              # 한 번의 forward
    q_taken = q_all.gather(1, u_a.unsqueeze(1)).squeeze(1)         # Q(s, u)
    baseline = (policy_probs * q_all).sum(1)                       # Σ π(u'^a) Q(s, (u^{-a}, u'^a))
    return (q_taken - baseline).detach()

# actor loss (에이전트마다, 파라미터 공유):
# loss = -(log_prob(u_a) * coma_advantage(...)).mean()

# 숫자로 확인: 다른 에이전트 행동이 고정됐을 때 내 행동 3개의 Q가 [2, 5, 1]이고
# 내 정책이 [0.2, 0.5, 0.3]이라면 baseline = 0.2*2 + 0.5*5 + 0.3*1 = 3.2
q_table = torch.tensor([[2.0, 5.0, 1.0]])
critic = lambda *args: q_table                                   # 위 Q를 내놓는 가짜 critic
probs = torch.tensor([[0.2, 0.5, 0.3]])
for a in range(3):
    print(a, round(coma_advantage(critic, probs, None, None, None, None, torch.tensor([a])).item(), 2))
# 0 -1.2 / 1 1.8 / 2 -2.2
```

팀 보상이 같더라도, 실제로 고른 행동이 "내 평소 정책의 평균(3.2)"보다 좋았는지에 따라 에이전트마다 다른 학습 신호를 받습니다. 1번 행동을 고른 에이전트는 +1.8로 강화되고, 2번을 고른 에이전트는 −2.2로 약화됩니다.

## 5. 실험: StarCraft Micromanagement

- 각 유닛이 **부분 관측**(시야 범위 안의 아군·적군 정보만)으로 행동
- 행동: **이동(4방향), 공격(적 지정), 정지, no-op**
- 맵: 3m(마린 3 vs 3), 5m(마린 5 vs 5), 5w(레이스 5 vs 5), 2d_3z(드라군 2 + 질럿 3) 등

비교 대상은 IAC 계열(독립 critic), centralised critic을 쓰지만 counterfactual baseline이 없는 변형 등이었습니다.

- COMA는 대부분의 맵에서 **승률이 가장 높았고**, 특히 유닛 종류가 섞인 맵에서 차이가 컸습니다.
- Centralised critic만 쓰는 것보다 **counterfactual baseline을 더할 때** 성능이 확실히 올랐습니다. Credit assignment가 실제로 중요하다는 증거입니다.
- 일부 맵에서는 centralised 접근을 쓰는 다른 방법들과 비슷하거나 더 좋은 성능을 냈습니다.

## 6. 정리

| 구성 | 역할 |
|---|---|
| Decentralised actor | 각자 자기 관측으로만 행동 (실행 시) |
| Centralised critic | 전역 상태 + joint action으로 $$Q(s, \mathbf{u})$$ (학습 시) |
| Counterfactual baseline | 나만 행동을 바꿨을 때의 평균 Q → **나의 기여도** |
| Critic 구조 | 다른 에이전트 행동을 입력, 내 모든 행동의 Q를 한 번에 출력 |

COMA는 이후 QMIX 같은 가치 분해 방법과 함께 MARL의 대표 baseline이 됐습니다.

> 다만 이후 표준 벤치마크가 된 SMAC(StarCraft II)에서는 COMA가 QMIX 같은 가치 분해 방법보다 성능이 낮게 나왔습니다(Samvelyan et al., 2019). on-policy actor-critic이라 샘플 효율이 낮고, joint action을 입력으로 받는 critic을 정확히 학습하기 어렵기 때문으로 해석됩니다. 반면 "반사실적 baseline으로 기여도를 나눈다"는 아이디어 자체는 이후 여러 MARL 연구에서 계속 쓰입니다.
