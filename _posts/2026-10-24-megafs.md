> 고해상도 교체는 세 가지 때문에 어려웠습니다. 종단간 프레임워크([FaceShifter]({% post_url 2026-10-24-faceshifter %}), [SimSwap]({% post_url 2026-10-24-simswap %}))의 **압축된 표현**은 고품질 생성에 정보가 부족하고, **적대 학습이 불안정**해 256²에 묶였으며, **GPU 메모리** 때문에 배치가 작아져 붕괴가 잦았습니다. [Disney]({% post_url 2026-10-24-hires-face-swapping %})는 1024²를 달성했지만 신원마다 디코더를 학습해야 했습니다. **MegaFS**(Zhu, Li, Wang, Xu, Sun, CASIA·마카오대, CVPR 2021)는 세 장벽을 각각 다른 도구로 넘습니다. 정보 손실은 **GAN 역변환**의 확장 잠재 공간으로, 불안정성은 **고정된 사전학습 StyleGAN2**를 디코더로 써서(판별기 없음), 메모리는 **세 부분을 따로 학습**해서. 소스와 목표 각 한 장만으로(원샷) 1024² 교체를 하는 첫 방법이고, 첫 메가픽셀 교체 데이터셋을 공개합니다.

## 1. 세 단계

**얼굴 인코딩: HieRFE와 W++.** StyleGAN의 $$\mathcal{W} \in \mathbb{R}^{512}$$보다 층마다 다른 코드를 주는 $$\mathcal{W}+ \in \mathbb{R}^{18 \times 512}$$가 재구성이 좋다는 것이 역변환 연구의 결론이었습니다. MegaFS는 여기에 StyleGAN2의 **상수 입력** $$C \in \mathbb{R}^{4 \times 4 \times 512}$$까지 예측 대상에 넣은 $$\mathcal{W}++$$를 제안합니다. HieRFE는 ResNet50 백본 + FPN 특징 피라미드 + 18개의 비선형 매핑 네트워크(다운샘플·conv·BN·LeakyReLU 반복 후 풀링)로 구성되고, 가장 작은 특징 맵에서 $$C$$와 저수준 코드 4개 $$L^{low}$$(위상 정보)를, 나머지에서 고수준 코드 14개 $$L^{high}$$(의미 정보)를 예측합니다. 손실은 픽셀 L2, LPIPS, ArcFace 신원, 랜드마크 L2(포즈·표정 제어용).

**잠재 조작: FTM.** 14개 고수준 코드마다 **Face Transfer Block**을 두고, 각 블록은 동일한 전이 셀 3개로 되어 있습니다. 소스·목표 코드를 이은 $$l_c$$에 대해

$$
T(l_c, l_s) = T_2(l_c, T_1(l_c, l_s)), \quad T_1(a, b) = \text{sigmoid}(K_1(a)) \times b, \quad T_2(a, b) = \tanh(K_2(a)) + b
$$

첫 단계는 (0,1) 게이트로 신원 외의 의미를 **버리고**, 둘째 단계는 작은 이동으로 목표 의미를 **조금 받아들입니다.** 목표 코드도 병렬로 처리해 목표 신원을 버리고, 최종 $$l_{s2t} = \sigma(\omega)\hat l_t + (1 - \sigma(\omega))\hat l_s$$로 학습 가능한 가중치로 섞습니다. 선형 의미 방향(InterFaceGAN)이 한 번에 한 속성만 바꾸는 것과 달리 **비선형 궤적**으로 여러 속성을 동시에 제어하고, 명시적 분리가 없습니다.

**생성.** 소스의 $$C_s$$, $$L^{low}_s$$는 신원 정보가 적어 버리고, 목표의 $$C_t$$, $$L^{low}_t$$와 $$L_{s2t}$$를 고정 StyleGAN2에 넣습니다. 잠재 공간에서 **전역적으로** 조작하므로 특징 맵의 국소 왜곡이 없고, 판별기가 없어 학습이 단순합니다. FTM 손실은 소스·목표 재구성, 목표와의 LPIPS, 소스 신원, 목표 랜드마크, 그리고 $$\lVert L^{high}_s - L_{s2t} \rVert_2$$ 정규화입니다.

## 2. 코드로 보기: 어느 층을 바꾸면 무엇이 바뀌나

18개 스타일 벡터의 저(1~4)·중(5~10)·고(11~18) 층 평균이 각각 배치, 얼굴 형태·눈 간격, 피부톤·조명을 정하는 toy 생성기에서, 소스 코드를 층 집합별로 바꿔 넣었을 때 네 속성이 어떻게 바뀌는지 보고, FTM 셀의 게이트·이동이 코드 노름을 어떻게 바꾸는지 봅니다.

```python
import torch
torch.manual_seed(0)
# a toy coarse-to-fine generator in the spirit of StyleGAN2: 18 style vectors; the first 4 (low) set layout, 5-10 shape/parts, 11-18 colour/texture
yy, xx = torch.meshgrid(torch.linspace(-1, 1, 32), torch.linspace(-1, 1, 32), indexing="ij")
def G(codes):                                      # codes: [18, 4]
    low, mid, high = codes[:4].mean(0), codes[4:10].mean(0), codes[10:].mean(0)
    cx, cy = 0.3 * torch.tanh(low[0]), 0.3 * torch.tanh(low[1])                          # layout: where the face is
    w, h = 0.6 + 0.2 * torch.tanh(mid[0]), 0.8 + 0.2 * torch.tanh(mid[1])                 # shape: face width/height (identity)
    eye = 0.2 + 0.1 * torch.tanh(mid[2])                                                  # part: eye spacing (identity)
    face = torch.exp(-(((xx - cx) / w) ** 2 + ((yy - cy) / h) ** 2) * 3)
    eyes = torch.exp(-(((xx - cx - eye) ** 2 + (yy - cy + 0.2) ** 2) * 60)) + torch.exp(-(((xx - cx + eye) ** 2 + (yy - cy + 0.2) ** 2) * 60))
    tone = 0.5 + 0.3 * torch.tanh(high[0]); light = 0.3 * torch.tanh(high[1]) * xx          # texture/colour: skin tone, lighting
    return face * (tone + light) - 0.5 * eyes
src, tgt = torch.randn(18, 4), torch.randn(18, 4)
def describe(codes):
    low, mid, high = codes[:4].mean(0), codes[4:10].mean(0), codes[10:].mean(0)
    return dict(layout=(0.3 * torch.tanh(low[0])).item(), width=(0.6 + 0.2 * torch.tanh(mid[0])).item(), eyes=(0.2 + 0.1 * torch.tanh(mid[2])).item(), tone=(0.5 + 0.3 * torch.tanh(high[0])).item())
ds, dt = describe(src), describe(tgt)
print(f"source: layout {ds['layout']:+.2f} width {ds['width']:.2f} eyes {ds['eyes']:.3f} tone {ds['tone']:.2f}")
print(f"target: layout {dt['layout']:+.2f} width {dt['width']:.2f} eyes {dt['eyes']:.3f} tone {dt['tone']:.2f}")
print("\nlatent code replacement (which layers take the SOURCE code):")
for name, sel in (("low 1-4 (layout)", slice(0, 4)), ("mid 5-10 (shape, parts)", slice(4, 10)), ("high 11-18 (colour)", slice(10, 18)), ("MegaFS: high-level 5-18, keep target C + low", slice(4, 18))):
    c = tgt.clone(); c[sel] = src[sel]; d = describe(c)
    print(f"  {name:<44} layout {d['layout']:+.2f} width {d['width']:.2f} eyes {d['eyes']:.3f} tone {d['tone']:.2f}")
print("-> swapping only the mid codes moves identity (shape, eye spacing) and keeps the target's layout and skin tone;")
print("   taking ALL high-level codes from the source also drags the source's colour/lighting along, the attribute leak MegaFS's FTM has to learn to suppress")
# FTM transfer cell: a sigmoid gate discards irrelevant semantics, then a tanh shift admits a little target information
l_s, l_t = src[6], tgt[6]; K1 = torch.randn(8, 4); K2 = torch.randn(8, 4)
l_c = torch.cat([l_s, l_t]); step1 = torch.sigmoid(K1.T @ l_c) * l_s; step2 = torch.tanh(K2.T @ l_c) + step1
print(f"\nFTM cell on layer 7: |l_s| {l_s.norm():.2f} -> after gate {step1.norm():.2f} -> after shift {step2.norm():.2f}; a two-step NON-LINEAR trajectory instead of a straight line between l_s and l_t")
```

```text
source: layout +0.01 width 0.64 eyes 0.219 tone 0.48
target: layout +0.00 width 0.59 eyes 0.179 tone 0.66

latent code replacement (which layers take the SOURCE code):
  low 1-4 (layout)                             layout +0.01 width 0.59 eyes 0.179 tone 0.66
  mid 5-10 (shape, parts)                      layout +0.00 width 0.64 eyes 0.219 tone 0.66
  high 11-18 (colour)                          layout +0.00 width 0.59 eyes 0.179 tone 0.48
  MegaFS: high-level 5-18, keep target C + low layout +0.00 width 0.64 eyes 0.219 tone 0.48
-> swapping only the mid codes moves identity (shape, eye spacing) and keeps the target's layout and skin tone;
   taking ALL high-level codes from the source also drags the source's colour/lighting along, the attribute leak MegaFS's FTM has to learn to suppress

FTM cell on layer 7: |l_s| 0.98 -> after gate 0.39 -> after shift 1.74; a two-step NON-LINEAR trajectory instead of a straight line between l_s and l_t
```

- 중간 층만 소스로 바꾸면 얼굴 너비(0.59 → 0.64)와 눈 간격(0.179 → 0.219)이 소스로 가고 배치·피부톤은 목표에 남습니다. 고층만 바꾸면 피부톤만 소스가 됩니다. MegaFS처럼 **고수준 코드 14개(5~18)를 모두** 소스에서 가져오면 신원과 함께 소스의 **피부톤(0.48)**까지 따라옵니다. 이것이 FSLSD·RAFSwap이 지적한 MegaFS의 약점(목표의 피부색·조명을 못 지킴)의 구조적 이유이고, FTM의 게이트와 목표 코드 혼합이 이를 학습으로 억제해야 합니다.
- FTM 셀은 소스 코드 노름을 게이트로 0.98 → 0.39로 줄였다가 이동으로 1.74로 바꿉니다. 두 코드 사이의 직선이 아닌 궤적이며, 논문은 이것이 선형 잠재 편집보다 여러 속성을 동시에 다룬다고 주장합니다.

## 3. 실험

**FF++(FaceShifter 프로토콜, 889 신원으로 수작업 정리).**

| 방법 | ID 검색 ↑ | 포즈 ↓ | 표정 ↓ |
|---|---|---|---|
| DeepFakes | 88.39 | 4.64 | 3.33 |
| FaceSwap | 72.69 | 2.58 | 2.89 |
| FaceShifter | 90.68 | 2.55 | 2.82 |
| MegaFS | **90.83** | 2.64 | 2.96 |

(재계산한 FaceShifter 수치는 원 논문의 97.38과 다릅니다.) 신원은 최고이지만 포즈·표정은 FaceShifter와 재연기 방법(Face2Face 2.68/2.09, Neural Textures 2.21/1.64)에 뒤집니다. 이유로 학습 이미지 50만 장(FaceShifter 270만 장, VGGFace 없음)과 FFHQ로 학습된 StyleGAN2의 **웃는 얼굴 편향**을 듭니다. 정성적으로 FaceShifter는 소스의 표정(사나움, 공포)을 가져오거나 목표의 수염을 남기는 반면 MegaFS는 신원을 더 잘 옮깁니다(Figure 5).

**CelebA-HQ 1024².** 30만 쌍에서 ID 유사도 0.5014, 포즈 3.58, 표정 2.87, FID 10.16을 이후 연구의 기준선으로 제시합니다. 주름, 홍채 색, 눈썹·코 모양이 소스에서 유지됩니다(Figure 6).

**Ablation.** $$\mathcal{W}++$$ 대 $$\mathcal{W}+$$: 역변환 LPIPS 0.2335 대 0.2486, MSE 0.056 대 0.067, 실패율 0.65% 대 1.28%, 교체 ID 0.58 대 0.54. $$\mathcal{W}+$$는 선글라스·안경·시선·복잡한 조명을 복원하지 못합니다(Figure 7). 잠재 조작: 단순 코드 교체(LCR) ID 0.40, SPADE형 ID 주입 0.44, FTM 0.50으로 FTM이 신원·포즈 최고.

## 4. 해석

**1. "StyleGAN 사전으로 교체" 계열을 열었습니다.** 고정 생성기 + 역변환 인코더 + 잠재 조작이라는 틀은 [FSLSD]({% post_url 2026-10-24-fslsd %})(층별 의미 분리), [RAFSwap]({% post_url 2026-10-24-rafswap %})(영역 토큰), [E4S]({% post_url 2026-10-24-e4s %})(영역별 역변환), [StyleIPSB]({% post_url 2026-10-24-styleipsb %})(신원 보존 기저)로 이어지며, 이들은 모두 MegaFS를 "흐리고, 경계가 보이고, 목표 조명을 못 지키는" 기준선으로 인용합니다. 위 toy의 피부톤 누출이 그 지적의 핵심이고, [StyleSwap]({% post_url 2026-10-24-styleswap %})은 아예 생성기를 다시 학습해 이 문제를 피합니다.

**2. 세 장벽을 세 도구로 분리한 논증이 명확합니다.** 정보 손실 → 확장 잠재 공간, 불안정성 → 판별기 없는 고정 디코더, 메모리 → 단계별 학습. 각각은 역변환·GAN 편집 연구에서 빌려온 것이지만 교체에 조합한 것이 기여이고, "원샷 메가픽셀"이라는 수식어가 그 결과입니다.

**3. 트레이드오프는 고정 생성기의 분포입니다.** FFHQ StyleGAN2가 만들 수 있는 얼굴만 만들 수 있어 웃는 얼굴 편향, 극단 포즈·조명의 실패, 배경·가림의 손실이 생깁니다. 후처리 마스크 블렌딩이 경계 아티팩트를 남긴다는 것이 RAFSwap의 지적이고, FSLSD는 생성기 특징을 목표 특징과 다중 스케일로 합쳐 해결합니다.

**4. 데이터셋 공개가 실용적 기여입니다.** CelebA-HQ 기반 30만 쌍의 메가픽셀 교체 데이터는 고해상도 위조 탐지 연구의 재료가 되고, 1024²에서의 ID·FID 기준선을 처음 제공했습니다.

**5. 평가를 읽을 때 주의할 점.** FF++의 FaceShifter 수치를 재계산하면서 신원 기준이 바뀌어(889 신원) 원 논문과 비교할 수 없고, MegaFS의 우위는 0.15%p 차이입니다. 포즈·표정 열세의 설명(데이터 양, 생성기 편향)은 검증되지 않은 가설입니다. 위 toy는 층별 역할을 손으로 정한 생성기라 실제 StyleGAN의 층별 의미가 그렇게 깨끗이 나뉘지는 않습니다.

## 5. 정리

| 항목 | 내용 |
|---|---|
| 장벽과 해법 | 압축 표현 → $$\mathcal{W}++$$ 역변환 / 불안정 GAN → 고정 StyleGAN2(판별기 없음) / 메모리 → 3부분 별도 학습 |
| HieRFE | ResNet50 + FPN + 18 매핑망, 상수 $$C$$ + 저수준 4 + 고수준 14 코드, 픽셀·LPIPS·ID·랜드마크 손실 |
| FTM | 14 블록 × 셀 3개, sigmoid 게이트(버림) → tanh 이동(수용), 학습 가중치로 소스·목표 혼합 |
| 생성 | 목표의 $$C$$, 저수준 코드 + $$L_{s2t}$$ → 고정 StyleGAN2, 1024² |
| 결과 | FF++ ID 90.83(최고), 포즈·표정은 열세; CelebA-HQ 1024² ID 0.50, FID 10.16; $$\mathcal{W}++$$가 $$\mathcal{W}+$$보다 우수 |
| 한계 | 소스 색·조명 누출, 흐림, 경계, 생성기 분포 편향, 배경·가림 |
