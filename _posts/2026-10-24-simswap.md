> 얼굴 교체는 두 갈래입니다. **소스 지향**([FSGAN]({% post_url 2026-10-24-fsgan %}), Nirkin 등)은 소스 얼굴에 목표의 표정·포즈를 입혀 붙이므로 소스의 포즈·조명에 민감하고 표정 재현이 부정확합니다. **목표 지향**(DeepFakes, IPGAN, [FaceShifter]({% post_url 2026-10-24-faceshifter %}))은 목표의 특징을 수정하므로 소스 변화에 강하지만, 신원 수정에 치우쳐 표정·시선이 어긋나곤 했습니다. **SimSwap**(Chen, Chen, Ni, Ge, 상하이교통대·Tencent, ACM MM 2020)은 목표 지향의 가장 단순한 형태를 찾습니다. DeepFakes가 한 쌍에만 되는 이유를 분석해 **ID 주입 모듈** 하나로 임의 신원으로 넓히고, 속성 보존은 속성마다 손실을 설계하는 대신 **약한 특징 매칭** 하나로 암묵적으로 걸었습니다. 이름 그대로 "Simple Swap"입니다.

## 1. DeepFakes의 한계

공유 인코더 $$Enc$$와 신원별 디코더 $$Dec_S$$, $$Dec_T$$. 학습은 워핑된 소스를 $$Enc$$-$$Dec_S$$로 복원하고 목표도 마찬가지입니다. 테스트에서 목표를 $$Enc$$-$$Dec_S$$에 넣으면 "워핑된 소스"로 착각해 소스 신원 + 목표 속성을 냅니다. 이때 인코더 특징에는 목표의 신원과 속성이 모두 있는데 $$Dec_S$$가 그것을 소스 신원 이미지로 바꾸므로, **소스 신원 정보가 $$Dec_S$$의 가중치 안에** 들어 있는 셈입니다. 그래서 디코더는 한 신원에만 쓸 수 있습니다([DeepFaceLab]({% post_url 2026-10-24-deepfacelab %})의 구조 분석과 같은 진단).

## 2. ID 주입 모듈

신원을 디코더에서 떼어 내기 위해 인코더와 디코더 사이에 **IIM**을 둡니다. 목표 특징 $$Fea_T$$에서 신원과 속성은 얽혀 있어 나눌 수 없으므로, **특징 전체를 수정**하되 손실이 어디를 바꾸고 어디를 남길지 암묵적으로 배우게 합니다. 소스에서는 ArcFace로 신원 벡터 $$v_S$$만 뽑고, 잔차 블록의 BN을 [AdaIN]({% post_url 2026-10-24-adain %})으로 바꾼 **ID-Block** 9개가 $$v_S$$에서 FC로 만든 $$\sigma_S, \mu_S$$로 특징을 변조합니다.

$$
\text{AdaIN}(Fea, v_S) = \sigma_S \frac{Fea - \mu(Fea)}{\sigma(Fea)} + \mu_S
$$

학습에 여러 신원의 소스가 섞이므로 디코더 가중치는 특정 신원과 무관해지고, 신원 수정은 IIM이, 복원은 디코더가 맡습니다. 신원 손실 $$1 - \cos(v_R, v_S)$$만 있으면 네트워크가 목표 속성을 다 버리고 소스 신원의 정면 얼굴만 내는 과적합이 생기므로, patchGAN 판별기의 적대 손실로 막습니다.

## 3. 약한 특징 매칭

속성을 하나씩 명시적으로 제약하려면 속성마다 네트워크가 필요해 비현실적입니다. pix2pixHD의 특징 매칭 $$\sum_{i=1}^{M} \frac{1}{N_i}\lVert D^{(i)}(I_R) - D^{(i)}(I_{GT}) \rVert_1$$은 정답이 있을 때 학습 안정화를 위한 것인데, 교체에는 정답이 없으므로 **목표 이미지 $$I_T$$를 정답 자리에** 넣고, **앞의 몇 층을 빼고 마지막 몇 층만** 씁니다.

$$
\mathcal{L}_{wFM}(D) = \sum_{i=m}^{M} \frac{1}{N_i} \lVert D^{(i)}(I_R) - D^{(i)}(I_T) \rVert_1
$$

얕은 층은 질감이라 픽셀 수준에서 결과를 목표에 묶어 신원 수정을 방해하고, 깊은 층은 의미(포즈, 표정, 조명 같은 속성)라 그것만 맞추면 속성이 암묵적으로 보존됩니다. 다중 스케일 판별기 둘에 모두 적용합니다. 총 손실은 $$10\mathcal{L}_{Id} + 10\mathcal{L}_{Recon} + \mathcal{L}_{Adv} + 10^{-5}\mathcal{L}_{GP} + 10\mathcal{L}_{wFM}$$이고, 재구성 손실은 같은 신원 쌍에서만 켭니다. VGGFace2에서 250픽셀 이상만 골라 224×224로 정렬, 같은 신원 배치와 다른 신원 배치를 번갈아 500에폭 이상 학습합니다.

## 4. 코드로 보기: 어느 층을 맞추느냐가 신원 변화를 결정한다

무작위 고정 4층 "판별기"에서, 목표 이미지(blob 위치 = 포즈, 입 크기 = 표정, 줄무늬 주파수 = 신원)를 신원 손실로 소스 신원 쪽으로 최적화하되 (a) 4층 모두, (b) 깊은 2층만, (c) 매칭 없음으로 특징 매칭을 걸고 신원 점수와 포즈·입 보존을 비교합니다.

```python
import torch, torch.nn as nn, torch.nn.functional as F
torch.manual_seed(0); torch.set_num_threads(1)
# a fixed random 'discriminator' with 4 layers; shallow layers see texture, deep layers see coarse layout (pose/expression)
D = nn.Sequential(nn.Conv2d(1, 8, 3, padding=1), nn.LeakyReLU(0.2), nn.Conv2d(8, 16, 4, stride=2, padding=1), nn.LeakyReLU(0.2),
                  nn.Conv2d(16, 32, 4, stride=2, padding=1), nn.LeakyReLU(0.2), nn.Conv2d(32, 32, 4, stride=2, padding=1)).eval()
for p in D.parameters(): p.requires_grad_(False)
def layers(img):
    outs, h = [], img
    for m in D:
        h = m(h)
        if isinstance(m, nn.Conv2d): outs.append(h)
    return outs
yy, xx = torch.meshgrid(torch.linspace(-1, 1, 32), torch.linspace(-1, 1, 32), indexing="ij")
def face(pose, mouth, tex_freq):           # layout = blob position + mouth size (attributes); texture = stripe frequency (identity)
    return torch.exp(-((xx - pose) ** 2 + yy ** 2) * 3) + mouth * torch.exp(-((xx - pose) ** 2 + (yy - 0.5) ** 2) * 20) + 0.25 * torch.sin(tex_freq * xx + 2 * yy)
target = face(0.2, 0.6, 4.0)[None, None]; source_id = 11.0
id_feat = lambda img: torch.stack([(img * torch.sin(source_id * xx + 2 * yy)).mean(), (img * torch.sin(4.0 * xx + 2 * yy)).mean()])   # a toy 'ArcFace': responds to the stripe frequency
def attr_err(img):                          # attribute error: blob centre and mouth energy vs the target
    w = img[0, 0].clamp(min=0); cx = (w * xx).sum() / w.sum(); m = (img[0, 0] * torch.exp(-((xx - 0.2) ** 2 + (yy - 0.5) ** 2) * 20)).mean()
    return (cx - 0.2).abs().item(), m.item()
tl = layers(target)
for name, start in (("full feature matching (all 4 layers)", 0), ("weak feature matching (last 2 layers)", 2), ("no feature matching", 4)):
    img = target.clone().requires_grad_(True); opt = torch.optim.Adam([img], 0.02)
    for s in range(400):
        f = id_feat(img); id_loss = 1 - F.cosine_similarity(f, torch.tensor([1.0, 0.0]), dim=0)     # pull towards the source identity
        fm = sum(F.l1_loss(a, b) for a, b in zip(layers(img)[start:], tl[start:])) if start < 4 else torch.tensor(0.0)
        loss = 10 * id_loss + 10 * fm; opt.zero_grad(); loss.backward(); opt.step()
    f = id_feat(img.detach()); cx_err, mouth = attr_err(img.detach())
    print(f"{name:<40} identity score {f[0].item() / (f.norm().item() + 1e-8):5.2f}   pose error {cx_err:.3f}   mouth energy {mouth:.3f} (target {attr_err(target)[1]:.3f})")
print("-> shallow-layer matching pins the pixels and blocks the identity change; deep-layer-only matching keeps layout (pose, mouth) while letting texture move")
```

```text
full feature matching (all 4 layers)     identity score  1.00   pose error 0.124   mouth energy 0.033 (target 0.035)
weak feature matching (last 2 layers)    identity score  1.00   pose error 0.140   mouth energy 0.027 (target 0.035)
no feature matching                      identity score  1.00   pose error 0.145   mouth energy 0.023 (target 0.035)
-> shallow-layer matching pins the pixels and blocks the identity change; deep-layer-only matching keeps layout (pose, mouth) while letting texture move
```

- 이 toy에서는 세 설정 모두 신원 점수가 1.00에 도달했고 포즈 오차도 0.12~0.15로 비슷합니다. 논문의 효과(얕은 층 매칭이 신원 변화를 막음)가 **재현되지 않았습니다.** 무작위 합성곱의 얕은 특징은 줄무늬 주파수 변화를 거의 구분하지 못해 픽셀을 묶는 힘이 약했고, 학습된 판별기의 얕은 층이 질감에 민감하다는 전제가 성립하지 않기 때문입니다. 입 에너지는 매칭이 많을수록 목표(0.035)에 가까워(0.033 → 0.027 → 0.023) 방향은 맞지만 차이가 작습니다.
- 논문의 표 1이 보여 주는 실제 차이는 전체 매칭(SimSwap-oFM)의 ID 검색이 가장 낮고, 매칭 없음(nFM)이 FaceShifter 수준으로 높으며, 약한 매칭이 중간에서 포즈를 가장 잘 지킨다는 것입니다. 이 toy로는 그 정량적 그림을 보일 수 없음을 그대로 적습니다.

## 5. 실험

**정성.** 영화 장면 8장의 목표 × 인터넷 10장의 소스(모두 학습 외)의 얼굴 행렬(Figure 3)에서 과장된 표정, 얼굴의 줄무늬, 큰 회전에도 신원을 바꾸면서 표정·시선·포즈·조명을 지킵니다. 소스는 신원 벡터만 쓰므로 정면·무표정일 필요가 없습니다.

**비교.** FaceForensics++에서 DeepFakes는 조명·포즈 불일치, FaceShifter는 결과가 좋지만 **표정과 시선이 목표를 완전히 따르지 않습니다**(Figure 4, 5의 가늘게 뜬 눈). FaceShifter는 얼굴 형태를 소스 쪽으로 바꾸는 강한 신원 수정 능력이 있지만 신원에 치우쳤다는 것이 저자들의 평가이고, 조명도 SimSwap이 약간 낫습니다(FaceShifter는 2단계가 있는데도). FSGAN은 표정·시선 재현에 실패하고 조명이 다르며, 소스 얼굴의 그림자를 결과에 끌어옵니다(Figure 6).

**정량(FF++, FaceShifter 프로토콜).** ID 검색은 SimSwap-oFM(전체 매칭)이 가장 낮고, SimSwap-nFM(매칭 없음)이 FaceShifter에 근접하며, SimSwap은 신원은 조금 뒤지지만 포즈 오차가 가장 좋습니다. 이후 논문들이 인용하는 수치는 ID 검색 92.83, 포즈 1.53(FaceShifter 97.38, 2.96)입니다. 표정은 유효한 재현이 없어 비교하지 않았습니다.

## 6. 해석

**1. 소스 지향 대 목표 지향이라는 분류를 정착시켰습니다.** 이 논문의 2절 분류는 이후 [HifiFace]({% post_url 2026-10-24-hififace %}), [E4S]({% post_url 2026-10-24-e4s %}), [FlowFace]({% post_url 2026-10-24-flowface %})가 자신을 위치시키는 좌표가 됩니다. 소스의 포즈·조명에 민감하다는 소스 지향의 약점과, 신원·속성의 얽힘이라는 목표 지향의 약점이 한 문단에 정리되어 있습니다.

**2. "단순함"이 가장 많이 쓰인 이유입니다.** 공개 코드와 사전학습 모델 덕에 SimSwap은 FaceShifter(비공개) 대신 가장 흔한 비교 기준이자 [MobileFaceSwap]({% post_url 2026-10-24-mobilefaceswap %})의 교사 모델이 됐습니다. 구조는 인코더-IIM-디코더 하나, 손실은 다섯 개뿐이고 특수 모듈이 없습니다. [Smooth-Swap]({% post_url 2026-10-24-smooth-swap %})이 추구한 "손수 만든 부품 없는 설계"의 선례입니다.

**3. 신원과 속성의 트레이드오프를 손실 하나로 조절합니다.** 약한 특징 매칭의 시작 층 $$m$$이 다이얼입니다. 깊은 층만 쓰면 신원이 강하고, 얕은 층까지 쓰면 속성이 강합니다. 이후 연구는 SimSwap을 "속성은 잘 지키지만 신원·얼굴 형태가 약하다"(HifiFace, [RAFSwap]({% post_url 2026-10-24-rafswap %}))고 평가하는데, 이는 설계의 선택이지 결함이 아닙니다. [FaceInpainter]({% post_url 2026-10-24-faceinpainter %})는 이 손실이 쌍 데이터용 지각 손실과 비슷해 결과가 목표를 닮는다고 지적합니다.

**4. 한계는 명시적 분리가 없다는 점입니다.** 특징 전체를 변조하므로 신원 벡터에 섞인 소스의 속성(머리, 안경, 조명)이 새고, 신원 강도를 올릴수록 속성이 무너집니다. [InfoSwap]({% post_url 2026-10-24-infoswap %})의 정보 병목, FaceShifter의 공간 마스크는 이 얽힘을 다른 방식으로 풉니다. 이마·뺨의 경계 아티팩트도 보고됩니다(FaceInpainter Figure 7).

**5. 평가를 읽을 때 주의할 점.** FaceShifter와의 비교는 논문에서 잘라 온 이미지로 이루어졌고, 표정 지표는 생략됐습니다. ID 검색 92.83은 FaceShifter 97.38보다 분명히 낮으며, 공개 모델은 논문의 모델과 달라 MobileFaceSwap이 재측정한 교사 수치(95.94)와 차이가 납니다. 위 toy는 논문의 핵심 효과를 재현하지 못했고 그 이유를 적어 두었습니다.

## 7. 정리

| 항목 | 내용 |
|---|---|
| 진단 | DeepFakes의 신원 특정성 = 신원이 디코더 가중치에 내장 |
| ID 주입 모듈 | ArcFace 벡터 → FC → AdaIN 파라미터로 목표 특징을 변조하는 ID-Block 9개, 디코더는 신원 무관 |
| 약한 특징 매칭 | 판별기의 **깊은 층**만 목표 이미지와 L1로 맞춰 속성을 암묵 보존 |
| 손실 | ID(10) + 같은 신원 재구성(10) + 힌지 적대 + GP + wFM(10), 다중 스케일 판별기 |
| 결과 | FF++ 포즈 오차 최저(1.53), ID 검색 92.83(FaceShifter 97.38), 표정·시선·조명 보존 우수 |
| 한계 | 신원·얼굴 형태 약함, 소스 속성 누출, 경계 아티팩트, 107M 파라미터 |
