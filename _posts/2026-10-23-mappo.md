> AlphaStar, OpenAI Five처럼 큰 성과는 PPO 같은 on-policy 방법으로 나왔지만, 학계의 협력 MARL은 [QMIX]({% post_url 2026-07-10-qmix %}) 같은 가치 분해와 MADDPG 같은 off-policy 방법이 주도했습니다. PPO가 샘플 효율이 나쁘다는 믿음과, 단일 에이전트의 구현 관행이 멀티에이전트에서는 통하지 않는다는 경험 때문입니다. **MAPPO 논문**(Yu, Velu, Vinitsky et al., Tsinghua·UC Berkeley, NeurIPS 2022 Datasets and Benchmarks)은 도메인 특화 변경 없이 최소한의 조정만 한 PPO가 네 벤치마크에서 off-policy 최고 방법들과 **대등하거나 더 좋고 샘플 효율도 비슷**함을 보였습니다. 새 알고리즘이 아니라 **실증과 설정 지침**이 기여입니다.

## 1. 설정

보상을 공유하는 DEC-POMDP입니다. 에이전트 $$i$$는 지역 관측 $$o_i = O(s; i)$$로 정책 $$\pi_\theta(a_i \mid o_i)$$를 돌리고, 공동 행동 $$A = (a_1, \ldots, a_n)$$에 공유 보상 $$R(s, A)$$를 받습니다.

- **MAPPO**: 정책 $$\pi_\theta$$와 가치 함수 $$V_\phi$$를 별도 네트워크로 두고, 가치 함수에 **전역 정보**를 넣습니다. 가치 함수는 분산 감소용으로 학습에만 쓰이므로 실행 때 없는 정보를 받아도 됩니다(CTDE).
- **IPPO**: 정책과 가치 함수 모두 지역 관측만 받는 독립 PPO.
- 동질 에이전트에서는 정책과 가치의 **파라미터 공유**, GAE와 advantage 정규화, 가치 클리핑 같은 일반적 PPO 관행을 씁니다. Recurrent 버전은 actor와 critic에 RNN을 두고 궤적을 길이 $$L$$의 chunk로 나눠 학습합니다.

## 2. 결과: 네 벤치마크

공정성을 위해 MADDPG와 QMix를 재구현하고 MAPPO와 같은 크기의 grid search로 조정했습니다. 한 데스크톱(64코어 CPU, RTX 3090 한 장)에서 돌렸습니다.

## 3. 다섯 가지 요인과 권고

### 가치 정규화

학습 중 실현 return이 크게 달라져 가치 목표가 요동치면 가치 학습이 불안정합니다. 가치 목표의 **running 평균과 표준편차**로 정규화해 회귀하고, GAE를 계산할 때는 역정규화합니다. Spread처럼 return이 -200에서 0까지인 환경에서 결정적이었고, SMAC 여러 맵에서도 최종 성능이나 분산이 좋아졌으며, 해로운 경우는 없었습니다.

> **권고 1**: 가치 정규화를 써라.

### 가치 함수의 입력

중앙화 PG와 분산 PG의 근본 차이는 critic의 입력입니다. 기존의 두 전역 상태에는 약점이 있습니다.

- **CL**(지역 관측의 연결): 에이전트 수에 따라 차원이 커지고, 어떤 에이전트도 못 보는 전역 정보가 빠집니다.
- **EP**(환경이 주는 전역 상태): 모든 에이전트에 공통인 정보라 에이전트 ID, 가능한 행동 같은 **지역 정보가 빠집니다**(SMAC가 그렇습니다).

그래서 EP와 $$o_i$$를 이어 붙인 **AS**(agent-specific global state)를 만들고, 둘 사이의 중복 feature를 제거한 **FP**(feature-pruned)도 만듭니다. SMAC에서 CL은 특히 에이전트가 많은 맵에서 효과가 없었고, EP는 어려운 맵에서 부족했으며, AS와 FP가 강했습니다. FP는 몇 맵에서 AS보다 좋았습니다. 차원, 에이전트별 feature, 전역 정보가 모두 중요합니다.

> **권고 2**: 가능하면 지역 에이전트별 feature와 전역 feature를 모두 critic에 넣되, 입력 차원을 불필요하게 키우지 마라.

### 학습 데이터 사용

단일 에이전트 연속 제어에서는 배치를 32~64 mini-batch로 쪼개 수십 epoch를 돌리는 것이 관행입니다. 멀티에이전트에서는 **샘플을 너무 자주 재사용하면 나빠집니다**. SMAC에서 15 epoch는 특히 MMM2와 Corridor에서 일관되게 차선 정책에 수렴하고, 5나 10 epoch가 좋았습니다. mini-batch도 **4개로 쪼개면 어떤 맵도 못 풀고** 1개가 23개 중 22개 맵에서 최고입니다. MARL의 비정상성 때문에 갱신당 정책 변화를 제한하는 것이 안정에 도움이 된다는 가설입니다. 쉬운 MPE 작업(Reference, Comm)에서는 어떤 값이든 같았고 Spread에서는 SMAC와 같은 경향입니다.

> **권고 3**: 어려운 환경은 최대 10 epoch, 쉬운 환경은 15 epoch. mini-batch로 쪼개지 마라.

### PPO 클리핑

$$\epsilon$$이 작으면 갱신당 정책 변화가 작아 안정적이지만 느립니다. 단일 에이전트의 관행 0.2보다 작은 **0.05**가 MMM2, 3s5z vs 3s6z 같은 어려운 맵에서 학습은 느리지만 최종 성능이 일관되게 높고 분산이 작았습니다. 0.2, 0.3, 0.5는 종종 차선에 머뭅니다.

> **권고 4**: $$\epsilon$$을 0.2 아래로 두고, 그 안에서 안정성과 속도의 균형으로 조정하라.

### 배치 크기

mini-batch 수가 고정되어 있으므로 배치가 클수록 기울기가 정확합니다. 거의 모든 경우 **임계 배치 크기**가 있어 그 아래서는 최종 성능이 나쁘고, 그 위에서 조정하면 최적의 성능과 샘플 효율이 나오며, 더 키우면 샘플 효율이 오히려 나빠집니다.

> **권고 5**: 큰 배치로 최고 성능을 얻은 뒤, 샘플 효율을 위해 배치를 조정하라.

## 4. 코드로 보기: 가치 정규화와 critic 입력이 학습을 가른다

에이전트 3명이 각자 90%만 정확한 관측으로 전역 상태(3가지)를 맞혀야 하는 협력 게임입니다. MPE Spread처럼 보상 스케일을 크게(성공 0, 실패 -200) 두고, critic 입력(자기 관측만 대 전역 상태 + 자기 관측)과 가치 정규화 유무를 바꿔 PPO로 학습합니다. mini-batch 없이 전체 배치로 5 epoch, $$\epsilon = 0.1$$입니다. 5 seed 평균 성공률입니다.

```python
import torch, torch.nn as nn, torch.nn.functional as F

torch.manual_seed(0); torch.set_num_threads(1)              # 재현성을 위해 단일 스레드
# 1) 협력 게임: 전역 상태 s ∈ {0,1,2}. 에이전트 3명이 각자 노이즈 낀 관측(90%만 정확)으로 행동을 고르고, 모두 s와 같으면 보상.
#    보상 크기를 MPE Spread처럼 수백 단위로 둔다(성공 0, 실패 -200)
N_S, N_AGENTS, P_CORRECT, R_FAIL = 3, 3, 0.9, -200.0
def env(batch):
    s = torch.randint(N_S, (batch,))
    obs = torch.stack([torch.where(torch.rand(batch) < P_CORRECT, s, torch.randint(N_S, (batch,))) for _ in range(N_AGENTS)], 1)
    return s, obs
def reward(s, acts): return torch.where((acts == s[:, None]).all(1), 0.0, R_FAIL)
def onehot(x, n): return F.one_hot(x, n).float()

class ValueNormalizer:                                      # Suggestion 1: 가치 목표의 running 평균·표준편차로 정규화(PopArt식)
    def __init__(self): self.mean, self.var, self.n = 0.0, 1.0, 0
    def update(self, x):
        self.n += 1; a = 1 / self.n
        self.mean = (1 - a) * self.mean + a * x.mean().item(); self.var = (1 - a) * self.var + a * x.var().item()
    def norm(self, x): return (x - self.mean) / (self.var ** 0.5 + 1e-8)
    def denorm(self, x): return x * (self.var ** 0.5 + 1e-8) + self.mean

def run(critic_input, normalize, iters=300, batch=512, epochs=5, eps=0.1, seed=0):
    """PPO로 에이전트들을 학습(파라미터 공유). critic_input: 'local'(자기 관측) 또는 'AS'(전역 상태 + 자기 관측)"""
    torch.manual_seed(seed)
    actor = nn.Sequential(nn.Linear(N_S + N_AGENTS, 32), nn.Tanh(), nn.Linear(32, N_S))
    critic = nn.Sequential(nn.Linear({"local": N_S, "AS": 2 * N_S}[critic_input] + N_AGENTS, 32), nn.Tanh(), nn.Linear(32, 1))
    opt = torch.optim.Adam(list(actor.parameters()) + list(critic.parameters()), 3e-3)
    vn = ValueNormalizer(); curve = []
    for it in range(iters):
        s, obs = env(batch); ids = onehot(torch.arange(N_AGENTS)[None].expand(batch, -1), N_AGENTS)
        x_actor = torch.cat([onehot(obs, N_S), ids], -1)
        g = onehot(s, N_S)[:, None].expand(-1, N_AGENTS, -1)
        x_critic = torch.cat([{"local": onehot(obs, N_S), "AS": torch.cat([g, onehot(obs, N_S)], -1)}[critic_input], ids], -1)
        with torch.no_grad():
            logits = actor(x_actor); acts = torch.distributions.Categorical(logits=logits).sample()
            logp_old = F.log_softmax(logits, -1).gather(-1, acts[..., None]).squeeze(-1)
            r = reward(s, acts); v = critic(x_critic).squeeze(-1)
            if normalize: vn.update(r); v = vn.denorm(v)                                           # GAE 계산 때는 원래 스케일로
            adv = r[:, None] - v                                                                  # 1-step이므로 A = r − V
            adv = (adv - adv.mean()) / (adv.std() + 1e-8)                                         # advantage 정규화
            v_targ = vn.norm(r) if normalize else r
        curve.append((r == 0).float().mean().item())                                              # 성공률
        for _ in range(epochs):                                                                   # mini-batch 없이 전체 배치로
            logp = F.log_softmax(actor(x_actor), -1).gather(-1, acts[..., None]).squeeze(-1)
            ratio = (logp - logp_old).exp()
            L_pi = -torch.min(ratio * adv, ratio.clamp(1 - eps, 1 + eps) * adv).mean()
            L_v = (critic(x_critic).squeeze(-1) - v_targ[:, None]).pow(2).mean()
            opt.zero_grad(); (L_pi + L_v).backward(); opt.step()
    return curve

print(f"관측을 그대로 따르는 정책의 성공률 ≈ {P_CORRECT ** N_AGENTS:.2f}")
for name, c, nz in [("IPPO,  정규화 없음", "local", False), ("IPPO,  가치 정규화", "local", True), ("MAPPO(AS), 정규화 없음", "AS", False), ("MAPPO(AS), 가치 정규화", "AS", True)]:
    m = torch.tensor([run(c, nz, seed=sd) for sd in range(5)]).mean(0)
    print(f"{name:24s}: 성공률 25회 {m[24]:.2f} | 50회 {m[49]:.2f} | 100회 {m[99]:.2f} | 300회 {m[-1]:.2f}")
```

```text
관측을 그대로 따르는 정책의 성공률 ≈ 0.73
IPPO,  정규화 없음           : 성공률 25회 0.48 | 50회 0.53 | 100회 0.52 | 300회 0.52
IPPO,  가치 정규화           : 성공률 25회 0.54 | 50회 0.57 | 100회 0.58 | 300회 0.57
MAPPO(AS), 정규화 없음       : 성공률 25회 0.46 | 50회 0.52 | 100회 0.54 | 300회 0.52
MAPPO(AS), 가치 정규화       : 성공률 25회 0.67 | 50회 0.71 | 100회 0.73 | 300회 0.71
```

- 정규화 없이 -200 스케일의 목표를 회귀하면 가치 손실이 공유 optimizer를 흔들어 두 설정 모두 0.52에서 멈춥니다. 권고 1의 Spread 상황입니다.
- 가치 정규화를 켜고 critic에 **전역 상태 + 자기 관측**(AS)을 주면 최적(0.73)에 도달합니다. 자기 관측만 보는 critic은 다른 에이전트가 무엇을 봤는지 몰라 보상을 설명하지 못하고, advantage의 노이즈가 커져 0.57에 머뭅니다. 권고 2의 핵심입니다.
- 둘 다 있어야 합니다. 정규화만 하면 0.57, AS만 하면 0.52입니다. 논문이 "요인은 서로 얽혀 있다"고 한 이유를 작은 게임에서도 봅니다.

## 5. 해석

**1. 논문의 주장은 "PPO가 최고"가 아니라 "PPO를 버릴 이유가 없다"입니다.** 도메인 특화 구조도, 내재 보상도, 사전학습도 없이 다섯 가지 설정만 맞추면 QMix, RODE, CDS, SAD와 대등합니다. 이후 MARL 연구가 MAPPO를 기본 기준선으로 쓰게 된 것은 이 실증 때문입니다. [Rainbow]({% post_url 2026-10-23-rainbow %})가 DQN 계열에서 한 일을 MAPPO는 협력 MARL의 PPO에서 했습니다.

**2. 권고들은 모두 비정상성을 겨냥합니다.** epoch을 줄이고, mini-batch를 쪼개지 않고, $$\epsilon$$을 작게 두는 것은 모두 **갱신당 정책 변화를 제한**합니다. 다른 에이전트의 정책이 바뀌면 환경이 바뀌는 MARL에서는 단일 에이전트보다 보수적인 갱신이 필요하다는 일관된 그림입니다. 단일 에이전트 관행(32 mini-batch, 수십 epoch, $$\epsilon = 0.2$$)을 그대로 옮기면 실패하는 이유입니다.

**3. critic의 입력 설계는 CTDE의 실질입니다.** "중앙화된 critic"이라는 말은 흔하지만 무엇을 넣느냐는 간단하지 않습니다. 전역 상태만으로는 에이전트별 정보가 빠지고(EP), 관측을 다 이으면 차원이 폭발합니다(CL). AS/FP는 그 사이의 실용적 답이고, 위 toy에서 지역 critic과의 차이(0.57 대 0.73)가 그 중요성을 보여 줍니다. Hanabi에서 인원이 늘수록 IPPO가 뒤처지는 것도 같은 이유입니다.

**4. IPPO가 생각보다 강하다는 점도 발견입니다.** 전역 정보 없이도 MPE와 대부분의 SMAC 맵에서 중앙화 off-policy 방법과 비슷합니다. 공유 보상의 협력 설정에서는 독립 학습이 꽤 멀리 간다는 뜻이고, 중앙화가 필요한 곳은 에이전트가 많거나(27m vs 30m, Hanabi 5인) 관측이 부분적인 경우입니다.

**5. 평가를 읽을 때 주의할 점.** 모든 환경이 이산 행동, 협력, 대부분 동질 에이전트입니다. 저자들도 경쟁 게임, 연속 행동, 이질 에이전트는 향후 과제로 남겼습니다. RODE, CDS, TiKick, SAD, VDN의 수치는 원 논문에서 가져왔고, QMix와 MADDPG만 재구현했습니다. 분석은 경험적이며 이론은 없습니다. 위 toy는 1-step 게임이라 GAE나 RNN 같은 요소는 다루지 않습니다.

## 6. 정리

| 항목 | 내용 |
|---|---|
| 주장 | 도메인 특화 변경 없는 PPO(MAPPO/IPPO)가 협력 MARL 네 벤치마크에서 off-policy SOTA와 대등 이상, 샘플 효율도 비슷 |
| MAPPO | 정책은 지역 관측, 별도의 critic에 전역 정보(CTDE). 동질 에이전트는 파라미터 공유 |
| 결과 | SMAC 23개 맵 대부분 QMix 이상, RODE와 대등. GRF 6개 중 5개 최고. Hanabi 5인 23.04(SAD 22.06). MPE QMix와 동등 |
| 권고 1 | 가치 목표를 running 통계로 정규화 |
| 권고 2 | critic에 전역 + 에이전트별 feature(AS/FP), 중복 차원 제거 |
| 권고 3 | 어려운 환경 ≤ 10 epoch, 쉬운 환경 15 epoch, mini-batch로 쪼개지 않기 |
| 권고 4 | $$\epsilon < 0.2$$(0.05가 안정적) |
| 권고 5 | 큰 배치로 성능 확보 후 샘플 효율에 맞춰 조정 |
